# 문서 탭 리뷰와 자동 업데이트

기준: `feat/copilot-document-tabs`, `cb5be7d`, 버전 `0.23.9`. 로컬 소스 변경이며 설치본 교체나 공개 배포는 하지 않았다.

## 리뷰에서 수정한 사항

- 임시 초안의 250ms 저장 타이머가 끝나기 전에 종료하면 마지막 편집이 유실될 수 있었다. 종료 확인 응답 전에 모든 최신 초안을 디스크에 저장한다. 저장 실패 시 종료를 승인하지 않는다.
- 초기 임시 초안 읽기 응답이 늦으면 그동안 새로 만든 초안을 덮어쓸 수 있었다. 현재 초안을 우선하여 병합한다.
- 설정에서 보관함을 바꾸는 경로가 모든 탭을 초기화했다. 열린 임시 문서 탭은 유지한다.
- 읽기 모드에 링크를 추가할 때 기존 본문의 마지막 공백까지 삭제했다. 원문을 보존하고 필요한 줄바꿈만 추가한다.
- 업데이트 실패 표시에서 두 값이 모두 없는 경우를 같은 버전으로 판단하여 오류를 두 번 표시했다. 실제 설치 시도와 릴리스 태그가 있을 때만 설치 오류를 표시한다. 기존 ZIP 업데이트 회귀 테스트에서 재현하고 수정했다.
- 설치 준비가 취소된 뒤 늦게 완료되어 앱 종료를 다시 요청할 수 있는 경합을 차단한다. 같은 설치 요청인지 확인하고, 종료 절차가 이미 실행 중이면 중복 실행기를 시작하지 않는다.

## 업데이트 동작

설치형 Windows x64 앱은 공식 Setup 다운로드와 SHA-256 검증 후 문서 저장 → 앱 종료 → 설치 → 재실행으로 이어진다. 설정의 `다운로드 후 자동 설치하고 다시 시작`은 기본 켜짐이다. 자동 확인/다운로드 설정과 별도로 끌 수 있다. ZIP 배포는 기존 수동 교체 절차를 유지한다.

입력, 한글 IME 조합, AI 생성, 녹음, 앱 작업, 열린 대화상자가 끝난 뒤 60초간 입력이 없으면 자동 설치를 요청한다. `지금 설치하고 다시 시작`으로 직접 실행할 수 있으며 `나중에`는 이번 실행의 자동 설치를 보류한다. 준비 도중 새 입력/작업이 발생하거나 저장 확인이 실패하면 설치를 연기한다. 기존 Copilot 미확정 편집과 임시 문서도 종료 저장 절차에 포함된다.

설치 파일을 앱 데이터의 별도 작업 폴더에 복사하고 다시 검증한다. 외부 PowerShell 실행기는 시작 확인 후 부모 앱이 정상 종료되기를 기다린다. 설치 직전에도 해시를 확인한다. 앱을 강제 종료하거나 Windows를 재부팅하지 않는다. Setup 완료 후 Dynote를 재실행하고 결과/설치 로그를 남긴다. 이전 시도와 버전을 기록하여 실패한 버전을 자동으로 반복 설치하지 않는다. 재실행된 버전이 업데이트 대상에 도달했을 때 작업 폴더를 정리한다.

명령행 옵션은 [Inno Setup 공식 문서](https://jrsoftware.org/inno-setup/documentation/topic_setupcmdline.htm)에 맞추었다. 기존 [skipifsilent Run 항목](https://jrsoftware.org/inno-setup/documentation/topic_runsection.htm)은 유지하여 실행기와 설치 프로그램이 중복으로 앱을 열지 않게 한다.

## 검증 결과

- `npm test`: 517개 통과, 실패 0.
- `npm run build`: 통과. 기존 큰 번들 안내만 남음.
- `node --check`: main, 설치 실행기, Windows 설치 검증 스크립트 통과. `git diff --check` 통과.
- 업데이트 관련 27개 테스트: 플랫폼 구분, 파일 변조 거부, 별도 설치 파일 보관, 실행기 시작 확인/실패/시간 초과, 동시 설정 차단, 실패 시도 기록, 자동 설치 끄기 보존, Windows BOM 오류 로그 읽기, 완료된 버전의 작업 파일 정리.
- `scripts/verify-update-install.mjs`: 실제 macOS Electron 화면과 제어된 설치 IPC로 기본 설정, 자동 설치 끄기, 설정 창 대기, 나중에, 입력/IME 대기, 60초 후 요청, 종료 저장 응답, 실패 버전 반복 억제와 수동 재시도 확인. 실제 설치 프로그램은 실행하지 않음.
- `scripts/verify-document-tabs.mjs` (`DYNOTE_NATIVE_DRAG=1`): 실제 마우스/Control 동작, 생성 중 다른 문서 이용, 완료/충돌/저장, 폴더 메뉴, 이동 취소/승인, 복사, 본문 링크/복귀 애니메이션 통과. 저장 타이머를 의도적으로 늦춘 상태에서 종료 응답 전에 마지막 편집이 디스크에 저장되는 것을 확인. 생성 중 업데이트 종료 요청은 거부되는 것도 확인. AI 응답은 제어된 IPC 사용.
- `scripts/verify-weekly-updates.mjs`: 기존 ZIP 다운로드 위치, 검증, 설정 보존, 오류 안내, 오프라인 후 기존 다운로드 열기 통과.

## 남은 Windows 검증

현재 macOS에서 `vmrun list`가 실행되지 않아 Windows PowerShell/Setup 실행과 실제 재실행은 검증하지 못했다. 이전 버전의 설치 성공 기록을 이번 자동 설치 검증으로 간주하지 않는다.

`scripts/verify-windows-installer.mjs`에 실제 앱의 설치 버튼 → 정상 종료 → Setup 결과 → 새 PID의 앱 시작 로그 → 노트/설정/패키지 보존 검증을 추가했다. 기존 Windows 배포 워크플로가 이 스크립트를 실행한다. 이 테스트는 Dynote가 설치되어 있지 않은 테스트 계정에서만 실행하며, 동일 패키지를 제어된 새 버전 피드로 재설치한다. 실제 두 버전 사이의 업그레이드 및 Windows 정책별 실행 확인은 별도로 필요하다. 이번 턴에서는 워크플로 실행, 원격 push, 릴리스 게시를 하지 않았다.
