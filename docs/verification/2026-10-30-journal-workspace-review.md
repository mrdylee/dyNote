# 저널·문서 비교·폴더 분류·주간 업데이트 구현 검토

2026-10-30 · Dynote 0.11.0 소스 기준 · `feat/editor-font-context-panels`

사용자의 재검토 후 구현·테스트 요청에 따라 Superpowers 계획, 테스트 우선 구현, 자체 코드 리뷰와 완료 검증을 진행했다. 공개 배포, 설치된 앱 교체, 버전 변경, 커밋·푸시는 진행하지 않았다. 기존 미추적 HANDOFF.md는 보존했다.

## 구현한 동작

| 기능 | 동작 |
| --- | --- |
| 문서 비교 | Markdown 파일·탭·영역 제목을 끌어 놓아 최대 3개를 나란히 열기. 배치 미리보기, 취소, 너비 조절, 영역 닫기, 버튼으로 옆에 열기 지원. 이미 열린 문서는 해당 영역으로 이동. |
| 편집 상태 | 파일 내용과 저장 대기열은 공유하고, 편집기·커서·선택·스크롤·보기 모드는 각 문서에서 유지. 툴바 명령과 AI 현재 문서 정보는 선택한 영역을 따른다. |
| 시작 저널 | 기본 시작 화면은 오늘과 과거 기록의 저널 피드. 신규 보관함은 Journal/YYYY-MM-DD.md. 기존 일지 폴더·형식·템플릿 보존. 보기만 해서는 파일을 생성하지 않고 ‘오늘 기록 시작’으로 생성. 설정에서 마지막 문서로 변경 가능. |
| 폴더 분류 | 저장된 일지의 제목·본문과 기존 폴더 이름을 기기 안에서 비교하여 제안. 대상 경로 수정·항목 제외·원문 보기·변경 미리보기 후 확정. 새 폴더 경로도 직접 지정 가능. |
| 원본 보존 | 저널 파일은 그대로 두고 대상 문서에 발췌와 출처 링크 추가. 같은 대상의 동일 발췌는 중복 추가하지 않음. 수정한 발췌는 확인 후 추가 버전으로 보존하며 기존 대상 내용을 덮어쓰지 않음. |
| 업데이트 | 마지막 정상 조회 후 7일이 지나면 자동 확인. 앱 실행 중 주기 확인, 시작 및 절전 복귀 때 확인. 앱 종료 중에는 다음 실행 시 확인. 수동 확인은 주기와 무관. |
| 다운로드 | 자동 확인·백그라운드 다운로드·시험 버전 포함·무시 버전 옵션. OS/CPU에 맞는 공식 ZIP만 선택. 크기와 SHA256 검증 후 준비 알림. 파일 위치 열기와 나중에 지원. |

## 검토 중 수정한 문제

- 단일 편집기 참조를 여러 영역이 공유하면 다른 문서에 명령이 적용될 수 있어 영역별 참조로 분리했다.
- 같은 보관함을 새로고침할 때 열어 둔 영역이 초기화되던 동작을 조정했다.
- 기존 문서 추출은 원본을 지우므로 재사용하지 않고 원본을 쓰지 않는 분류 계획을 추가했다. 미리보기 이후 변경은 거부하고 기존 Vault 복구·롤백 경로를 사용한다.
- 복사한 참조 링크가 대상 문서의 같은 이름으로 다른 주소를 가리키면 적용을 거부하고 새 문서 경로를 안내한다.
- 내부 문서 드래그가 본문에 텍스트로 삽입되는 경로와 취소 후 미리보기 잔류를 막았다.
- 저널 피드에서는 숨겨진 문서의 편집·AI 컨텍스트가 노출되지 않도록 했다.
- 업데이트 설정 저장과 자동 조회가 겹치는 경우를 직렬화했다. 실패한 조회는 이전 성공 결과를 표시하지 않는다.
- 기존 시험 버전·무시 목록 설정을 승계하고, 공개 Mac 파일 이름의 macos-arm64 형식을 반영했다.

## 검증 결과

- 전체 Node 테스트: **293 통과, 실패 0, 건너뜀 0**.
- 제품 빌드: 성공. 기존 대형 번들 경고는 남아 있다.
- 변경 형식 검사: 통과.
- `scripts/verify-journal-workspace.mjs`: 격리된 실제 Mac Electron에서 저널 열기 무변경, 3개 영역/4번째 제한, 드래그 취소, 내부 드래그 텍스트 삽입 방지, 파일별 저장, AI 문서 정보와 시간 삽입 명령의 활성 영역 연결, 새로고침 유지, 분류 제외/미리보기/확정, 원본 동일성, 옵션 저장, 두 시작 화면의 재시작 복원 통과. 페이지 오류 없음.
- `scripts/verify-weekly-updates.mjs`: 통제된 배포 응답과 시험용 바이트로 실제 앱의 수동 확인, 백그라운드 다운로드, 무결성 검증, 준비 안내, 릴리스 설명의 비실행 텍스트 표시, 오프라인 오류, 기존 옵션 승계 통과. 실제 배포 ZIP을 받거나 설치하지 않았다.
- `scripts/verify-editor-tools.mjs`: 기존 목록 이동·되돌리기·접기, Mermaid 삽입·되돌리기와 실제 SVG 표시 통과.
- 공식 GitHub 목록 읽기 확인: 시험 버전 포함 시 Mac arm64에는 v0.10.1의 `Dynote-0.10.1-macos-arm64.zip`, Windows x64에는 v0.11.0의 `Dynote-0.11.0-windows-x64.zip` 선택. 두 파일 모두 서버 SHA256 정보가 있었다. 테스트의 비교 기준 버전은 0.9.0이며, 현재 소스 0.11.0에 대한 업그레이드 가능성을 뜻하지 않는다.

재현: 프로젝트의 `npm test`, `npm run build` 및 위 검증 스크립트. Electron 스크립트는 설치된 Playwright 경로를 `DYNOTE_PLAYWRIGHT_MODULE`로 지정하며 임시 보관함과 임시 앱 설정을 사용한다. 화면 결과는 `output/playwright/journal-document-comparison.png`, `journal-startup.png`에 있다.

## 실제 범위와 배포 조건

- 분류는 로컬 제목·내용·폴더 일치 규칙이다. AI 의미 분류나 요약이 아니며, 일치하지 않는 주제는 사용자가 경로를 지정해야 한다.
- 원본과 분류 문서의 자동 양방향 동기화는 하지 않는다. 사용자가 편집한 대상 내용은 보존한다.
- 현재 ZIP 배포는 **검증 다운로드 후 직접 설치**다. 자동 앱 교체·재시작 설치는 별도 설치형 배포와 서명 준비가 필요하다. [Electron 업데이트 안내](https://www.electronjs.org/docs/latest/api/auto-updater/)
- GitHub 공식 API의 배포 파일 digest를 검증에 사용하며, digest가 없는 파일은 검증 완료로 표시하지 않는다. [GitHub 배포 파일 API](https://docs.github.com/en/rest/releases/assets)
- 확인 당시 최근 공개본들은 시험 버전으로 표시되어 있어 해당 채널은 ‘시험 버전 포함’ 옵션으로 조회한다.
- 실제 Windows 실행, 설치형 업데이트, macOS Developer ID 서명·공증은 이번 검증 범위에 포함되지 않는다.
- Logseq와 동일한 내부 구조나 완전 호환을 주장하지 않는다. 앞선 REA 번들 분석은 메모리 한도로 완결되지 않았으며, 이번 구현은 공개 동작을 참고해 Dynote 소스 구조에 맞췄다.
