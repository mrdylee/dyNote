# 날짜·세부사항 없이 자동 초안 저장

2026-11-01, macOS arm64 / Dynote 0.12.2 로컬 수정본.

## 확인한 원인과 동작

- 날짜, 대상, 단계, 메모, 준비 작업은 기존 데이터 모델에서도 선택사항이었다. 실제 설치본에서 103개 인식 결과의 날짜가 비어 있었고, 남은 5개 대상 행의 원본 대조 체크 때문에 등록 버튼이 비활성화된 것을 확인했다.
- 캡처 인식과 독립적인 원본 대조가 끝나면 AI 초안으로 자동 저장한다. 입력 폼이나 원본 대조 체크를 요구하지 않는다. 읽힌 값만 채우고 모르는 날짜·세부사항은 빈칸으로 유지한다.
- `draft` 상태로 AI 초안을 구분한다. 대조상 누락·병합·미확인 문제가 있으면 기존 불확실성 설명을 유지하고, 설명이 없는 항목에는 `원본 대조 필요`를 표시한다. 저장을 막는 조건으로 사용하지 않는다.
- 기존 보관함의 다른 일정 상태는 바꾸지 않는다. 수동 저장은 제목만 있어도 가능하다. 잘못된 날짜와 외부 파일 변경에 대한 검증은 유지한다.
- 자동 저장 실패 시 원본과 전체 인식 결과를 화면에 유지하고 한 번의 저장으로 재시도할 수 있다. 대조 실패·취소에도 초기 결과를 날짜 입력이나 확인 체크 없이 저장할 수 있다. 늦은 응답은 취소 결과를 덮어쓰지 않는다.

## 검증

- 수정 전: 초안 상태 검사 실패, 실제 Electron에서 99개 결과가 자동 저장되지 않는 회귀 실패 확인.
- 수정 후: 전체 단위 테스트 326개, production build, diff check 통과.
- 실제 Electron 검증 35개 그룹 통과: 초안·대조 7, 캡처 8, AI 제공자 공유 10, Planner 전체 흐름 10. 앞의 25개는 최종 Mac 패키지에서도 실행했다.
- 99개 날짜 미정 일정이 입력·체크 없이 저장되고 모두 `draft`로 유지됐다. 수동 일정도 제목만으로 저장됐다. 저장 실패·취소·누락/병합 경고·재시도·중복 캡처·사용자 수정 날짜 보존·외부 충돌·재실행을 확인했다.
- 패키지 dist/core/electron/licenses 파일 273개가 소스·빌드와 일치하고 엄격한 번들 서명 무결성 검사가 통과했다. ASAR SHA-256: `e7a0d21f3fc000700873273aba1c25aca01bad103926865d5e9dabfd8152aba0`.

## 실제 설치본과 기존 결과 보존

- 실제 앱의 미등록 103개 결과를 날짜·세부내용을 추가 입력하지 않고 기존 저장 경로로 먼저 보관했다. 기존 버전에서는 표시상 확인 체크를 완료해 등록 잠금을 풀었지만, 원본의 정확성을 확인했다고 주장하지 않는다. 보존한 결과는 모두 AI 초안으로 구분했다.

- 기존 앱은 `Dynote Install Backups/2026-11-01-auto-drafts-AR1HZJ/Dynote.app`에 백업하고 `/Applications/Dynote.app`을 교체했다. 원본 일정 파일 백업은 같은 비공개 폴더의 `private-board-before-drafts.md`에 있으며 패키지와 Git에는 포함하지 않는다.
- 설치된 ASAR가 검증 패키지와 일치한다. 앞선 대상명 접두사로 인한 중복 수정도 포함한다. 개인 내용을 추가로 AI에 전송하거나 공개 배포하지 않았다.
- 실제 설치본을 정상 재실행한 뒤 Codex 인증과 GPT-6.1-Sol 선택 유지, Studio의 전체 103개와 AI 초안 표시를 확인했다. 날짜·세부사항을 채우지 않고 이어서 사용할 수 있는 상태로 열어 두었다.
