# 저널 정렬과 Copilot 대화 저장 검증

2026-11-19 · 로컬 수정 · Windows 설치본에는 아직 배포하지 않음

## 확인한 문제와 변경

- 파일 트리가 저널 파일도 이름 오름차순으로 정렬했다. 보관함의 일간 저널 설정으로 날짜를 해석해 최신순으로 표시한다. 일반 폴더의 이름순 정렬과 Copilot 세션 제목·경로는 유지한다.
- 수동 Copilot 가져오기에서 모든 보관함의 미확정 AI 편집을 검사해, 팀 노트의 초안 때문에 개인 노트 가져오기가 막혔다. 저장할 개인 보관함의 편집 상태만 검사한다. 개인 노트에 미확정 변경이 있으면 설정에 해당 문서로 이동하는 버튼을 표시하고, 변경 유지·되돌리기를 선택할 때까지 가져오기를 차단한다. 기록 폴더 연결은 가능하며 변경 검토 후 전체 대화 가져오기를 누르면 된다.
- 로컬 VS Code Agent Host의 `.copilot/session-state`가 검색 대상에 없었다. `COPILOT_HOME` 또는 사용자 홈의 `.copilot` 아래에서 선택한 로컬 프로젝트와 경로가 일치하는 VS Code 세션만 읽는다. 독립 CLI 세션·다른 프로젝트·미완료 대화·내부 추론은 가져오지 않는다. 기존 WSL 연결과 재가져오기 중복 방지를 유지한다.
- 설정 탭·제목·접근성 이름을 `Copilot 대화 자동 저장`으로 통일했다. 첫 가져오기 때 `Copilot Note`가 생성되는 점과 WSL Agent Host 기록 폴더 연결을 안내한다.
- 기록 폴더 선택 직후 모든 프로젝트의 완료된 대화를 과거 날짜까지 가져온다. 프로젝트·세션 체크박스와 `세션 불러오기`를 제거했다. 이미 연결한 폴더는 `전체 대화 가져오기`로 다시 가져온다. 설정을 여는 것만으로 기존 선택 범위를 바꾸거나 저장하지 않는다.
- 자동 저장 설정을 적용하면 이후 발견되는 프로젝트도 포함한다. 전체 프로젝트의 활성화 시점을 저장하고 설정을 다시 적용해도 유지한다. 수동 가져오기는 이 시점과 무관하게 모든 날짜를 가져오며, 중복 방지·삭제 제외는 유지한다.

- `scripts/verify-journal-navigation.mjs`: 기본 날짜·사용자 지정 날짜 형식·연도/월/일 하위 폴더의 최신순 표시, 일반 폴더 이름순 유지, 개인·팀 저널 탐색 통과.
- `scripts/verify-copilot-capture-drafts.mjs`: 폴더 선택 직후 가져오기, 프로젝트·세션 선택 UI 제거, 다른 보관함 초안과 원본 보존, 개인 노트 미확정 변경의 저장 차단·문서 이동·되돌린 후 가져오기 활성화 통과.

## 리뷰 후 추가 수정

리뷰 범위는 `559a759` 이후 이 작업의 미커밋 변경이다. 로컬 코드 리뷰와 실패 재현 후 수정으로 확인했다.

1. **Copilot 세션 식별과 저장 형식 선택**: 화면 기록과 Agent Host 기록의 파일명이 다르면 같은 대화를 두 번 처리하고, 파일명이 같으면 다른 대화를 누락할 수 있었다. 세션 고유 ID로 후보를 묶고, 이미 가져온 대화는 기존 메시지 ID와 호환되는 형식을 우선한다. 처음 가져오는 대화는 완료된 화면 기록을 우선한다. 저장한 세션의 원본 ID를 보존해 다른 세션의 삭제 제외 설정이 잘못 적용되지 않게 했다. 별도 파일명의 동일 세션, 화면 기록이 나중에 생긴 Agent Host 세션의 계속 가져오기, 파일명 충돌 후 한 세션만 삭제하는 시나리오를 회귀 테스트로 추가했다.
2. **중첩 저널 정렬**: `YYYY/MM/DD` 형식은 파일만 최신순이고 연도·월 폴더는 오름차순이었다. 저널 저장 폴더 내부의 하위 폴더에도 가장 최근 기록 날짜를 적용했다. 저널 폴더 자체와 다른 최상위 폴더의 순서는 바꾸지 않는다. 실제 Electron에서 이전 순서로 실패한 뒤 최신순으로 통과하는 것을 확인했다.
3. **전체 가져오기와 재시도**: 두 프로젝트의 서로 다른 과거 날짜 대화, 손상된 개별 기록 제외, 삭제 후 재가져오기 방지, 중단된 저장 복구 후 나머지 대화 가져오기, 기존 일별 문서 이관과 새 대화 가져오기를 컨트롤러에서 검증했다.
4. **자동 저장 활성화 시점**: 새 프로젝트가 생긴 뒤 설정을 다시 저장하면 이전 활성화 이후의 대화도 누락될 수 있었다. 해당 회귀 테스트에서 가져온 기록 수가 0으로 실패하는 것을 확인한 후, 모든 프로젝트가 동일한 활성화 시점을 유지하도록 고쳤다.
