# 개발 플래너

왼쪽 반짝임 아이콘 **개발 플래너**를 엽니다. 오늘·일정·근거 세 보기에서 같은 일정을 관리합니다.

## 캡처에서 시작하기

1. PPT 일정표를 이미지로 캡처한 뒤 플래너에 붙여넣습니다. 파일 선택과 드롭도 가능합니다. PNG·JPEG·WebP 한 장, 최대 6MB를 지원합니다.
2. GitHub Copilot에 연결되어 있고 이미지 지원 모델을 사용할 수 있으면 **붙여넣은 이미지가 해당 모델로 자동 전송되어 분석됩니다.** 미연결 상태에서는 원본을 유지하며 GitHub 연결 → 연결 확인 → 일정 인식하기를 사용할 수 있습니다. 수동 일정 추가에는 AI 연결이 필요 없습니다.
3. 원본 옆의 추출 결과에서 제목·대상·단계·날짜를 수정하고 등록할 항목을 선택합니다. 연도가 없거나 불명확하면 날짜 미정으로 남깁니다. AI의 날짜·텍스트·표시 영역은 잘못 인식될 수 있으므로 등록 전 확인하세요.
4. **선택한 항목 등록**을 누릅니다. 같은 원본 항목은 중복 등록에서 제외하며 기존 일정을 덮어쓰지 않습니다.

Link/BMS/PACK, CV/DV/PD/PV는 입력 제안입니다. 이름을 자유롭게 바꿀 수 있으며 단계의 의미나 순서를 자동으로 정하지 않습니다. PPTX 파일 자체나 여러 장 일괄 분석은 지원하지 않습니다.

## 준비와 브레인스토밍

일정 카드를 누르면 날짜, 상태, 메모와 준비 작업을 수정할 수 있습니다. **함께 생각하기**에 고민을 입력하고 대안을 비교하세요. 질문과 해당 일정의 내용만 Copilot에 전송합니다. **채택**한 대안만 준비 작업에 추가되고 **보류**한 대안은 결정 기록으로 남습니다. 원본/직접 기록과 AI 제안 채택을 구분합니다.

상세 화면은 **저장**으로 확정합니다. 닫기·변경 취소는 저장 전 수정을 버립니다. 플래너를 떠나거나 앱을 종료하기 전에 저장하세요. 저장 실패 시 열린 화면의 초안은 유지되지만 강제 종료 복구용 초안 저장소는 제공하지 않습니다. 저장 직후 안내의 실행 취소로 이전 보드 상태를 복원할 수 있습니다. 그 사이 문서가 바뀌면 되돌리기를 거부합니다.

일정 보기의 막대를 끌면 기간을 유지하며 날짜가 이동합니다. 막대를 클릭하거나 키보드 Enter/Space를 누르면 상세 화면에서 날짜를 수정할 수 있습니다. 날짜 미정 항목은 오늘 보기에서 확인하세요.

## V모델 근거

요구사항·설계·구현·시험·결과 종류로 보관함의 노트를 연결합니다. 연결 후 원문이 바뀌면 재검토 필요를 표시합니다. 문서를 검토한 뒤 해당 연결의 확인 버튼으로 현재 버전을 기록할 수 있습니다. 결과에는 미확인·통과·실패를 직접 지정합니다. **문서가 연결되었다는 것만으로 시험 통과나 개발 단계 완료를 판정하지 않습니다.** 단계 진행을 강제로 잠그지 않습니다.

현재는 일정별 문서 연결과 변경 표시입니다. 개별 요구사항 ID의 전체 추적성, 시험 도구의 결과 자동 수집, 변경 영향 전파는 포함하지 않습니다. ubCode는 별도 예제로 검사 가능성을 평가했으며 앱에 내장하거나 자동 실행하지 않습니다. [평가 결과](verification/ubcode-planner.md)

## 저장 위치

선택한 보관함의 `Projects/Development Board.md`에 `dynote_planner` YAML 속성과 읽을 수 있는 Markdown 요약을 저장합니다. 원본 이미지는 `_attachments/`에 보관합니다. 생성 요약은 YAML의 표시용 사본이므로 플래너에서 편집하세요. 생성 영역 밖에 쓴 메모와 다른 YAML 속성은 보존합니다.

보드는 최대 500개 일정을 저장합니다. 해당 경로에 다른 문서가 있거나 속성이 손상되어 있으면 오류를 표시하고 저장하지 않습니다. 외부 수정과 충돌하면 초안을 복사한 뒤 새로고침하여 다시 확인하세요. 캡처를 등록하지 않고 닫아도 이미 가져온 원본 첨부파일은 보관함에 남습니다.
