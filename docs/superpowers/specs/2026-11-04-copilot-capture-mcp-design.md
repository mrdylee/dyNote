# VS Code Copilot 대화 수집과 Dynote MCP 설계 검토

작성일: 2026-11-04 (Asia/Seoul)
상태: MCP 계획 보류. 사용자가 우선 자동 저널 기록과 제목 삭제 버튼, 가져오기 버튼을 요청했다. 현재 구현 범위는 2026-11-04-copilot-journal-auto-design.md가 정의한다. 이 문서는 향후 MCP 검토용으로 보존한다.

## 목적과 확인한 요구

- VS Code Copilot에서 필요한 작업 대화를 개인 기록으로 남긴다.
- 기본 결과는 대화 기록 문서와 오늘 저널의 링크다. AI 요약과 할 일 자동 생성은 포함하지 않는다.
- 불필요한 대화를 매번 삭제하는 부담을 줄인다. 사용자는 세션을 자주 새로 여므로 매 세션의 기록 시작 요청을 기본으로 요구하지 않는다.
- 저널에서 관리되는 AI 기록 항목을 삭제하면 수집 기록도 함께 휴지통으로 이동한다. 링크만 제거하는 별도 모드는 제공하지 않는다.
- 삭제한 기록을 백그라운드 수집이 다시 생성해서는 안 된다. VS Code 원본 대화는 변경하지 않는다.

## 확인한 현재 상태

소스 기준은 v0.15.2, a7f8df07fc97b8afa83f8e24d68935caa972d138이다. 로컬 설치 메타데이터는 VS Code 1.145.0, Copilot 0.73.0이다. 실행 중인 세션의 종류나 Hook 실행 성공은 아직 검증하지 않았다.

현재 Dynote는 외부 MCP를 사용하는 클라이언트 설정을 제공한다(electron/ai-extensions.mjs). 외부에서 개인 기록을 전달받는 MCP 서버와 Copilot 수집기는 없다. 하나의 활성 보관함과 GitController를 사용한다. 새 기능은 기존 저장 큐, 보관함 식별, revision 검사와 recovery를 재사용해야 한다.

공식 문서는 Copilot sessionStart의 세션 식별과 context 전달, agentStop의 transcript 경로를 설명한다. VS Code Hooks는 Preview이며 Local/Copilot 세션의 이벤트 형식을 구분해야 한다. 특히 기존 Local transcript 형식은 안정된 API가 아니다. 문서 지원과 해당 설치본의 실행 지원을 구분한다.

## 대안 비교

| 대안 | 장점 | 한계 |
|---|---|---|
| MCP만으로 명시적 전송 | 불필요한 기록이 적고 연결이 간단함 | 모델이 넘긴 텍스트만으로 전체 원문 보존을 주장할 수 없음. 매번 전송 요청이 필요함 |
| 모든 대화를 저널로 자동 등록 | 사용자 동작이 적음 | 잡담이 쌓임. AI 중요도 판단은 누락과 사용량이 발생함 |
| 프로젝트 자동 수집 + MCP로 프로젝트 기록 시작/중단 | 프로젝트를 한 번 지정하면 새 세션도 이어서 기록. 저널은 프로젝트별 하루 한 항목 | 해당 프로젝트의 잡담도 포함될 수 있음. Hook과 세션 식별을 먼저 검증해야 함 |

추천은 세 번째다. MCP는 기록할 프로젝트와 제외할 세션을 지정하는 인터페이스이고, Hook은 허용된 프로젝트의 수집을 담당한다. 기본 기록 단위는 프로젝트와 날짜이며, 세션은 원문 출처를 구분하는 단위다. 두 경로는 같은 원본 식별자와 저장 서비스를 사용한다. 매 세션을 선택하는 방식은 필요할 때 한 번만 저장하는 보조 기능으로 한정한다.

## 제안하는 기본 동작

최초에 사용자가 프로젝트와 개인 보관함을 연결하고 수집을 켠다. 프로젝트별 설정은 개인 프로필에 저장한다. 프로젝트 저장소에 팀 공통 Hook을 자동 추가하지 않는다. 개인 용도가 확인된 보관함만 대상이며, 공간을 바꿔도 수신 대상이 팀 공간으로 바뀌지 않는다.

1. 허용한 프로젝트의 새 대화를 로컬 임시 수집함에 보관한다. 저널에는 아직 추가하지 않는다.
2. 사용자가 Copilot에게 “이 프로젝트의 대화를 Dynote에 자동 기록해 줘”라고 한 번 요청한다.
3. MCP가 해당 프로젝트의 자동 기록을 활성화하고 현재 응답의 완료를 기다리는 저장 요청을 남긴다. 모델이 대화 전문을 다시 작성해서 보내는 것을 원문으로 취급하지 않는다.
4. 현재 답변이 끝나고 Hook 수집이 확인되면 Dynote가 오늘의 프로젝트 기록 문서와 저널 링크를 만든다. 활성화 전 과거 임시 수집을 임의로 소급 등록하지 않으며, 과거 기록은 명시적으로 선택해서 가져온다.
5. 같은 프로젝트에서 이후 새로 연 세션과 재개한 세션도 그날의 문서에 자동 반영한다. 프로젝트 자동 기록 상태는 앱/VS Code 재시작과 날짜 변경 후에도 유지하며 매번 시작을 요청하지 않는다.
6. “이 프로젝트 기록 중단”은 프로젝트의 이후 정식 기록 반영을 멈추고 이미 기록한 내용은 유지한다. 수집 자체를 끄는 설정은 임시 수집도 멈춘다. “이 세션 이후 기록 제외”는 해당 세션의 이후 반영만 중단하며 기존 기록은 유지한다. 기존 내용까지 지우려면 별도의 명확한 삭제 동작을 사용한다. 한 번 저장은 지정한 완료 범위만 기록한다.

위의 문장은 사용자 경험 예시다. 실제 MCP tool 이름, UI 메뉴 및 Hook 설치는 호환성 검증 뒤 구현한다. AI 요약, 중요도 분류, 작업 완료 추론은 이 경로의 필수 기능이 아니다.

## 보관과 저널 표시

임시 수집함은 보관함과 Git 폴더 밖의 앱 데이터에 둔다. 제안 기본 보관 기간은 마지막 수집 후 7일이며, 최초 활성화 화면에서 명시한다. 선택해서 정식 기록한 내용에는 임시 보관 기간을 적용하지 않는다. 임시 기록을 매일 검토하라는 알림은 제공하지 않는다. 수집을 끄면 새 대화 읽기와 저장을 중단한다.

정식 기록은 프로젝트별 현지 날짜별 Markdown 문서 하나에 저장하고, 그날의 저널에 링크를 하나 만든다. 세션 열 개를 새로 열어도 문서 하나와 저널 링크 하나다. 문서 내부에서 세션 제목과 시각으로 원문 구간을 구분하고 내부 entry ID를 붙인다. 프로젝트는 canonical 경로에 연결한 내부 ID로 구분하므로 이름이 같은 다른 프로젝트를 합치지 않는다. 날짜는 메시지 발생 시점의 사용자 현지 날짜이며, 지연 수신했다고 도착 날짜로 바꾸지 않는다. 날짜를 넘어 이어지는 세션의 새 메시지는 새 날짜의 문서에 넣고 이전 날짜의 문서를 중복 복사하지 않는다.

프로젝트의 모든 대화를 기록하는 설정은 작업과 무관한 질문도 포함할 수 있다. 하루 한 링크는 저널의 항목 수를 줄이는 정책이며, 대화의 의미를 자동으로 판별하는 정책이 아니다. 초기에 AI 중요도 필터를 필수로 넣지 않으며, 사용자가 지정한 작업 프로젝트와 세션 제외 범위에 따라 기록한다.

정식 기록 문서와 저널은 현재 보관함의 Git 백업 규칙을 따른다. 최초 활성화 화면에서 실제 개인 공간과 백업 원격을 함께 보여 준다. 임시 수집함은 Git 자동 백업 대상이 아니다. 이 기능에서 push, 공유, Git 권한 변경을 자동 실행하지 않는다.

## 역할과 데이터 흐름

- 수집기: 검증한 Hook 형식에서 세션/프로젝트/시각과 대화 원문을 확보하고 임시 수집함에 기록한다. 사용자 질문과 표시되는 assistant 응답을 우선 대상으로 삼는다. 도구 출력, 첨부 바이너리, 내부 추론까지 보존한다는 약속은 하지 않는다. 코드 블록이 질문/응답에 포함되면 해당 텍스트는 범위에 포함된다.
- MCP 서버: 개인 설정으로 허용한 수집 항목의 목록과 프로젝트 자동 기록 시작/중단, 세션 제외, 한 번 저장, 전송 상태를 제공한다. 임의 보관함 경로나 transcript 파일 경로를 모델 입력으로 받아 쓰지 않는다.
- Dynote 수신부: 기존 문서 저장 규칙으로 개인 문서와 저널 링크를 반영하고 화면을 갱신한다.

세션 식별은 실행 환경, canonical 프로젝트 경로, 원본 세션 ID의 조합으로 한다. 여러 창에서 가장 최근 파일을 임의로 현재 대화로 간주하지 않는다. Copilot harness에서는 sessionStart context로 현재 수집 참조를 전달하는 안을 검증한다. 참조가 없거나 여러 후보가 있으면 범위가 제한된 후보 선택을 요구한다. MCP roots는 workspace 참고 정보이며, 그 자체를 파일 접근 권한이나 보관함 권한으로 취급하지 않는다.

MCP 저장 요청은 요청 시점의 완료된 범위와 현재 진행 중인 turn을 구분한다. 요청을 먼저 영속화하고, 마지막 응답 수집 이후 적용한다. Hook을 기다리며 MCP 응답을 붙잡지 않는다. 대기 중에는 “전송 예약”, 문서 반영 뒤에는 “저장 완료”를 반환한다. 응답이 중단되거나 지원하지 않는 transcript를 만나면 부분 수집/미완료로 표시한다.

원본 메시지 ID가 있다면 이를 이용한다. 없으면 parser가 검증한 snapshot revision과 메시지 순서/내용으로 중복을 판정한다. 같은 텍스트를 두 번 물었다고 한 메시지를 제거하는 전역 content-hash 방식은 사용하지 않는다. 재전송, Hook 중복, 프로세스 재시작 뒤에도 동일 revision의 반영은 한 번이다. 요약/압축으로 과거 메시지가 줄어든 snapshot이 와도 기존 원문을 지우지 않는다.

프로젝트 자동 기록 여부는 매 수신 시 확인하고, 시작/중단/제외 변경에는 증가하는 설정 revision을 부여한다. 기록 시작 전 수집된 메시지와 중단 이후 메시지는 자동 소급 등록하지 않는다. 새 세션과 재개 세션은 현재 프로젝트 설정을 사용하되 삭제/제외 표식을 우선한다. 수집 실패, 형식 변경, 권한 오류는 내용을 로그에 출력하지 않고 세션별 상태로 드러낸다. 자동 수집은 관찰만 하며 Copilot의 응답을 차단하거나 계속 생성하도록 강제하지 않는다. 복사/내보내기 파일 가져오기는 형식이 지원되지 않는 환경에서 사용자가 선택할 수 있는 별도 복구 경로다.

## 앱 종료와 보관함 전환

수집기는 Dynote 창이 닫혀 있어도 실행될 수 있으므로 임시 수집과 저장 요청을 로컬에 남긴다. MCP 응답은 이 상태를 “전송 대기”로 표시한다. 첫 범위에서는 설정된 개인 보관함을 Dynote에서 열었을 때 기존 저장 큐로 반영한다. 다른 보관함에 쓰거나 보이지 않는 별도 Vault 인스턴스를 만들어 우회하지 않는다. 현재 저널을 편집 중이면 초안을 먼저 안전하게 저장하고 revision 충돌 시 대기한다.

## 삭제와 복원

저널의 관리되는 AI 기록 항목은 해당 프로젝트의 해당 날짜 문서를 가리키는 편집 단위다. 저널 항목을 삭제하면 그날의 프로젝트 기록 전체를 휴지통으로 옮기고 해당 날짜를 자동 반영 제외로 먼저 표시한다. 대기 중인 수신도 이 제외 상태를 확인한다. 삭제 메뉴에는 포함된 세션 수를 표시한다. 다른 날짜의 기록과 이후 날짜의 프로젝트 자동 기록 상태는 유지한다.

개별 대화는 프로젝트 기록 문서 안의 관리되는 세션 구간에서 삭제할 수 있다. 이 동작은 선택한 구간과 대응하는 임시 사본만 정리하고 해당 원본 세션을 이후 자동 반영에서 제외한다. 다른 세션과 다른 날짜에 이미 저장된 원문은 임의로 지우지 않는다. 단순한 “기록 중단/제외” 명령은 기존 내용을 삭제하지 않는다.

삭제는 제외 상태 기록, 문서/구간 및 연결된 자동 링크의 복구 사본 확보, 원문 사본 정리를 하나의 복구 가능한 작업으로 처리한다. 임시 사본에 다른 날짜/세션의 데이터가 있으면 그 범위를 보존하고 삭제된 범위만 제거한다. 사용자가 직접 작성한 주변 문장과 수동으로 복사한 일반 링크는 자동 수정하지 않는다. 일반 링크의 글자 수정, 블록 이동, 외부 파일 변경을 내용 삭제로 추정하지 않는다. Delete/Backspace는 관리되는 항목 전체를 삭제한 편집 의도를 식별할 때만 연동한다.

실행 취소/복원은 기록과 자동 생성 링크를 함께 복원한다. 삭제로 생긴 자동 반영 제외는 사용자가 재개할 때 해제하며 복원 직후 이미 대기 중이던 내용을 무조건 추가하지 않는다. 일부만 삭제된 경우 앱은 완료를 표시하지 않고 복구 사본과 재시도 상태를 유지한다. 이 동작에 필요한 operation journal은 기존 recovery에 맞춰 구현하고 완전한 보관함 트랜잭션을 주장하지 않는다.

VS Code 원본과 과거 Git 커밋은 삭제 범위가 아니다. 사용자가 명시적으로 재등록하기 전에는 삭제 제외 상태를 해제하지 않는다.

## 검증 기준과 단계

먼저 로컬 macOS/Windows Copilot 세션을 대상으로 한다. WSL/SSH/컨테이너 및 Cloud는 별도의 전송/실행 환경 확인 전에는 지원으로 표시하지 않는다.

첫 단계는 호환성 검증이다. 임시 프로젝트의 합성 대화로 Hook 이벤트와 transcript 범위, 여러 창의 세션 식별, 저장 요청과 마지막 응답의 순서를 확인한다. 지원한 버전/세션 종류별 parser fixture를 확보한 다음 구현 계획을 확정한다.

최종 기능의 통과 기준:

- 수집을 켜지 않은 프로젝트에는 기록이 생기지 않는다.
- 임시 수집만 켠 프로젝트의 대화 20건에는 저널 링크가 0개다.
- 자동 기록을 한 번 켠 프로젝트에서 같은 날 새 세션 10개와 추가 응답 5회, 이벤트 재생 3회 후 프로젝트 기록 문서와 저널 링크는 각각 하나다. 원문은 세션별로 구분되어 모두 남는다.
- 다음 날과 재시작 뒤에도 프로젝트 설정은 유지되고 새 메시지는 새 날짜의 문서에 한 번만 들어간다. 시작 전/중단 후 범위를 임의로 소급 등록하지 않는다.
- 기록 시작 도구 호출 이후의 마지막 답변이 빠지지 않으며 미완료는 미완료로 표시된다.
- 모델이 넘긴 재작성 텍스트를 원본으로 표시하지 않는다. 사용자/assistant 원문 범위와 누락 범위를 기록한다.
- 저널에서 삭제하면 그날의 프로젝트 문서와 자동 링크가 사라지고 대기 이벤트 재생/재시작 후 재등장하지 않는다. 다음 날 기록과 다른 프로젝트는 유지한다.
- 문서 안의 한 세션 구간 삭제는 다른 세션/날짜를 지우지 않으며 해당 세션의 이후 수신은 제외된다.
- 복원하면 기록과 링크가 함께 돌아온다. 다른 사용자 문장은 그대로다.
- 같은 프로젝트의 여러 세션과 여러 프로젝트 창 사이에 잘못된 연결이 없다.
- 개인/팀 전환, 앱 종료, 현재 저널 편집, 다른 프로세스의 수정 중에도 데이터를 덮어쓰거나 잘못된 공간에 저장하지 않는다.
- 임시 수집은 Git에서 제외되고 정식 기록만 기존 백업 정책을 따른다.

## 자체 검토

- 확정된 요구(대화+링크, 연동 삭제, 잦은 새 세션)와 제안 기본값(7일 임시 보관, 프로젝트 자동 기록, 날짜별 문서)을 구분했다.
- 자동 수집과 저널 자동 등록을 구분했고, MCP가 모델에 없는 원문을 만들어낼 수 있다고 가정하지 않았다.
- 현재 turn 완료 전 저장 요청, 다중 창 오연결, 프로젝트 설정의 시작/중단 경계, 날짜별 기록, 삭제 범위와 재수집, Git 전송, 앱 종료 중 전달을 검토했다.
- 실제 Hook/transcript 호환성은 검증 전이며 완료/구현/배포로 표현하지 않는다.
