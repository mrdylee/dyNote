# VS Code Copilot 대화 수집과 Dynote MCP 설계 검토

작성일: 2026-11-04 (Asia/Seoul)
상태: 검토 초안. 제품 구현, 실제 대화 수집, 사용자 설정 변경, 배포를 수행했다는 의미가 아니다.

## 목적과 확인한 요구

- VS Code Copilot에서 필요한 작업 대화를 개인 기록으로 남긴다.
- 기본 결과는 대화 기록 문서와 오늘 저널의 링크다. AI 요약과 할 일 자동 생성은 포함하지 않는다.
- 불필요한 대화를 매번 삭제하는 부담을 줄인다.
- 저널에서 관리되는 AI 기록 항목을 삭제하면 수집 기록도 함께 휴지통으로 이동한다. 링크만 제거하는 별도 모드는 제공하지 않는다.
- 삭제한 기록을 백그라운드 수집이 다시 생성해서는 안 된다. VS Code 원본 대화는 변경하지 않는다.

## 확인한 현재 상태

소스 기준은 v0.15.2, a7f8df07fc97b8afa83f8e24d68935caa972d138이다. 로컬 설치 메타데이터는 VS Code 1.145.0, Copilot 0.73.0이다. 실행 중인 세션의 종류나 Hook 실행 성공은 아직 검증하지 않았다.

현재 Dynote는 외부 MCP를 사용하는 클라이언트 설정을 제공한다(electron/ai-extensions.mjs). 외부에서 개인 기록을 전달받는 MCP 서버와 Copilot 수집기는 없다. 하나의 활성 보관함과 GitController를 사용한다. 새 기능은 기존 저장 큐, 보관함 식별, revision 검사와 recovery를 재사용해야 한다.

공식 문서는 Copilot sessionStart의 세션 식별과 context 전달, agentStop의 transcript 경로를 설명한다. VS Code Hooks는 Preview이며 Local/Copilot 세션의 이벤트 형식을 구분해야 한다. 특히 기존 Local transcript 형식은 안정된 API가 아니다. 문서 지원과 해당 설치본의 실행 지원을 구분한다.

## 대안 비교

| 대안 | 장점 | 한계 |
|---|---|---|
| MCP만으로 명시적 전송 | 불필요한 기록이 적고 연결이 간단함 | 모델이 넘긴 텍스트만으로 전체 원문 보존을 주장할 수 없음. 매번 전송 요청이 필요함 |
| 모든 대화를 저널로 자동 등록 | 사용자 동작이 적음 | 잡담이 쌓임. AI 중요도 판단은 누락과 사용량이 발생함 |
| 자동 임시 수집 + MCP로 기록 시작/중단 | 원문 확보와 사용자 선택을 결합. 작업 대화마다 한 번 선택하면 됨 | Hook, 로컬 보관, 세션 연결의 호환성을 먼저 검증해야 함 |

추천은 세 번째다. MCP는 기록 대상을 고르는 인터페이스이고, Hook은 선택 여부와 관계없이 허용된 프로젝트의 수집을 담당한다. 두 경로는 같은 원본 식별자와 저장 서비스를 사용한다.

## 제안하는 기본 동작

최초에 사용자가 프로젝트와 개인 보관함을 연결하고 수집을 켠다. 프로젝트별 설정은 개인 프로필에 저장한다. 프로젝트 저장소에 팀 공통 Hook을 자동 추가하지 않는다. 개인 용도가 확인된 보관함만 대상이며, 공간을 바꿔도 수신 대상이 팀 공간으로 바뀌지 않는다.

1. 허용한 프로젝트의 새 대화를 로컬 임시 수집함에 보관한다. 저널에는 아직 추가하지 않는다.
2. 사용자가 Copilot에게 “이 대화를 Dynote 작업 기록으로 계속 남겨 줘”라고 요청한다.
3. MCP가 해당 세션에 기록 시작을 예약한다. 모델이 대화 전문을 다시 작성해서 보내는 것을 원문으로 취급하지 않는다.
4. 현재 답변이 끝나고 Hook 수집이 확인되면 Dynote가 개인 대화 문서와 오늘 저널 링크를 만든다.
5. 이후 같은 세션의 응답은 Hook으로 같은 문서에 자동 반영한다. 추가 전송 요청은 필요 없다.
6. “기록 중단”은 이후 자동 반영을 멈추고 이미 기록한 내용은 유지한다. 한 번만 저장하는 기능은 반복 수집을 켜지 않고 완료된 범위만 기록한다.

위의 문장은 사용자 경험 예시다. 실제 MCP tool 이름, UI 메뉴 및 Hook 설치는 호환성 검증 뒤 구현한다. AI 요약, 중요도 분류, 작업 완료 추론은 이 경로의 필수 기능이 아니다.

## 보관과 저널 표시

임시 수집함은 보관함과 Git 폴더 밖의 앱 데이터에 둔다. 제안 기본 보관 기간은 마지막 수집 후 7일이며, 최초 활성화 화면에서 명시한다. 선택해서 정식 기록한 내용에는 임시 보관 기간을 적용하지 않는다. 임시 기록을 매일 검토하라는 알림은 제공하지 않는다. 수집을 끄면 새 대화 읽기와 저장을 중단한다.

정식 기록은 보관함의 Markdown 문서로 저장한다. 원래 세션 ID가 아닌 내부 record ID로 경로를 만들고 사용자가 읽을 제목은 별도로 둔다. 같은 세션은 하나의 문서에 누적하고, 대화가 있었던 각 날짜의 저널에 링크를 한 번씩 만든다. 링크 날짜는 수집 이벤트 발생 시점의 사용자 현지 날짜이며, 지연 수신했다고 도착 날짜로 바꾸지 않는다.

정식 기록 문서와 저널은 현재 보관함의 Git 백업 규칙을 따른다. 최초 활성화 화면에서 실제 개인 공간과 백업 원격을 함께 보여 준다. 임시 수집함은 Git 자동 백업 대상이 아니다. 이 기능에서 push, 공유, Git 권한 변경을 자동 실행하지 않는다.

## 역할과 데이터 흐름

- 수집기: 검증한 Hook 형식에서 세션/프로젝트/시각과 대화 원문을 확보하고 임시 수집함에 기록한다. 사용자 질문과 표시되는 assistant 응답을 우선 대상으로 삼는다. 도구 출력, 첨부 바이너리, 내부 추론까지 보존한다는 약속은 하지 않는다. 코드 블록이 질문/응답에 포함되면 해당 텍스트는 범위에 포함된다.
- MCP 서버: 개인 설정으로 허용한 수집 항목의 목록과 기록 시작, 한 번 저장, 중단, 전송 상태를 제공한다. 임의 보관함 경로나 transcript 파일 경로를 모델 입력으로 받아 쓰지 않는다.
- Dynote 수신부: 기존 문서 저장 규칙으로 개인 문서와 저널 링크를 반영하고 화면을 갱신한다.

세션 식별은 실행 환경, canonical 프로젝트 경로, 원본 세션 ID의 조합으로 한다. 여러 창에서 가장 최근 파일을 임의로 현재 대화로 간주하지 않는다. Copilot harness에서는 sessionStart context로 현재 수집 참조를 전달하는 안을 검증한다. 참조가 없거나 여러 후보가 있으면 범위가 제한된 후보 선택을 요구한다. MCP roots는 workspace 참고 정보이며, 그 자체를 파일 접근 권한이나 보관함 권한으로 취급하지 않는다.

MCP 저장 요청은 요청 시점의 완료된 범위와 현재 진행 중인 turn을 구분한다. 요청을 먼저 영속화하고, 마지막 응답 수집 이후 적용한다. Hook을 기다리며 MCP 응답을 붙잡지 않는다. 대기 중에는 “전송 예약”, 문서 반영 뒤에는 “저장 완료”를 반환한다. 응답이 중단되거나 지원하지 않는 transcript를 만나면 부분 수집/미완료로 표시한다.

원본 메시지 ID가 있다면 이를 이용한다. 없으면 parser가 검증한 snapshot revision과 메시지 순서/내용으로 중복을 판정한다. 같은 텍스트를 두 번 물었다고 한 메시지를 제거하는 전역 content-hash 방식은 사용하지 않는다. 재전송, Hook 중복, 프로세스 재시작 뒤에도 동일 revision의 반영은 한 번이다. 요약/압축으로 과거 메시지가 줄어든 snapshot이 와도 기존 원문을 지우지 않는다.

수집 실패, 형식 변경, 권한 오류는 내용을 로그에 출력하지 않고 세션별 상태로 드러낸다. 자동 수집은 관찰만 하며 Copilot의 응답을 차단하거나 계속 생성하도록 강제하지 않는다. 복사/내보내기 파일 가져오기는 형식이 지원되지 않는 환경에서 사용자가 선택할 수 있는 별도 복구 경로다.

## 앱 종료와 보관함 전환

수집기는 Dynote 창이 닫혀 있어도 실행될 수 있으므로 임시 수집과 저장 요청을 로컬에 남긴다. MCP 응답은 이 상태를 “전송 대기”로 표시한다. 첫 범위에서는 설정된 개인 보관함을 Dynote에서 열었을 때 기존 저장 큐로 반영한다. 다른 보관함에 쓰거나 보이지 않는 별도 Vault 인스턴스를 만들어 우회하지 않는다. 현재 저널을 편집 중이면 초안을 먼저 안전하게 저장하고 revision 충돌 시 대기한다.

## 삭제와 복원

저널의 관리되는 AI 기록 항목은 record ID를 가진 편집 단위다. 해당 항목의 삭제는 다음 작업을 하나의 복구 가능한 작업으로 처리한다.

1. 기록을 자동 수집에서 제외 상태로 먼저 기록한다.
2. 정식 대화 문서와 그 기록을 가리키는 자동 생성 저널 항목들을 휴지통/복구 사본으로 옮긴다.
3. 임시 수집함의 동일 세션 사본도 제거한다.
4. 해당 세션의 추적을 중단한다. 이미 대기 중이던 수신도 제외 상태를 확인하고 적용하지 않는다.

같은 기록이 여러 날짜의 저널에서 사용 중이면 삭제 메뉴에 영향을 받는 날짜 수를 표시한다. 사용자가 직접 작성한 주변 문장과 수동으로 복사한 일반 링크는 자동 수정하지 않는다. 일반 링크의 글자 수정, 블록 이동, 외부 파일 변경을 내용 삭제로 추정하지 않는다. Delete/Backspace는 관리되는 항목 전체를 삭제한 편집 의도를 식별할 때만 연동한다.

실행 취소/복원은 기록과 자동 생성 링크를 함께 복원한다. 복원된 세션은 추적이 일시 중단된 상태이며 사용자가 기록 재개를 선택할 수 있다. 일부만 삭제된 경우 앱은 완료를 표시하지 않고 복구 사본과 재시도 상태를 유지한다. 이 동작에 필요한 operation journal은 기존 recovery에 맞춰 구현하고 완전한 보관함 트랜잭션을 주장하지 않는다.

VS Code 원본과 과거 Git 커밋은 삭제 범위가 아니다. 사용자가 명시적으로 재등록하기 전에는 삭제 제외 상태를 해제하지 않는다.

## 검증 기준과 단계

먼저 로컬 macOS/Windows Copilot 세션을 대상으로 한다. WSL/SSH/컨테이너 및 Cloud는 별도의 전송/실행 환경 확인 전에는 지원으로 표시하지 않는다.

첫 단계는 호환성 검증이다. 임시 프로젝트의 합성 대화로 Hook 이벤트와 transcript 범위, 여러 창의 세션 식별, 저장 요청과 마지막 응답의 순서를 확인한다. 지원한 버전/세션 종류별 parser fixture를 확보한 다음 구현 계획을 확정한다.

최종 기능의 통과 기준:

- 수집을 켜지 않은 프로젝트에는 기록이 생기지 않는다.
- 임시 대화 20건을 수집해도 선택하지 않은 대화의 저널 링크는 0개다.
- 선택한 세션의 추가 응답 5회와 이벤트 재생 3회 후 문서는 하나이고 날짜별 링크도 하나다.
- 기록 시작 도구 호출 이후의 마지막 답변이 빠지지 않으며 미완료는 미완료로 표시된다.
- 모델이 넘긴 재작성 텍스트를 원본으로 표시하지 않는다. 사용자/assistant 원문 범위와 누락 범위를 기록한다.
- 저널에서 삭제하면 연결된 문서와 자동 링크가 사라지고 대기 이벤트 재생/재시작 후 재등장하지 않는다.
- 복원하면 기록과 링크가 함께 돌아온다. 다른 사용자 문장은 그대로다.
- 같은 프로젝트의 여러 세션과 여러 프로젝트 창 사이에 잘못된 연결이 없다.
- 개인/팀 전환, 앱 종료, 현재 저널 편집, 다른 프로세스의 수정 중에도 데이터를 덮어쓰거나 잘못된 공간에 저장하지 않는다.
- 임시 수집은 Git에서 제외되고 정식 기록만 기존 백업 정책을 따른다.

## 자체 검토

- 확정된 요구(대화+링크, 연동 삭제)와 제안 기본값(7일 임시 보관, 세션 추적)을 구분했다.
- 자동 수집과 저널 자동 등록을 구분했고, MCP가 모델에 없는 원문을 만들어낼 수 있다고 가정하지 않았다.
- 현재 turn 완료 전 저장 요청, 다중 창 오연결, 삭제 후 재수집, Git 전송, 앱 종료 중 전달을 검토했다.
- 실제 Hook/transcript 호환성은 검증 전이며 완료/구현/배포로 표현하지 않는다.
