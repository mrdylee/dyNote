# Journal editing ergonomics

The user reports four follow-up problems in v0.15.0 and has already authorized review, fixes and deployment in this thread.

- Keep a stable classification control row while a daily journal is open. The existing `status === saved` condition drops suggestions during typing and unmounts the banner every autosave cycle. Keep the row mounted, let its review availability reflect saved suggestions, prevent narrow-width text wrapping, and render its explanation as an overlay. Hiding the entire row on another document remains normal navigation.
- Add an accessible context menu on file/folder rows in the left tree. Files use existing confirmation, revision checking, app recovery copy and undo. Ordinary folders use an explicit confirmation and Electron system trash, preserving all descendants and unknown file types. Protect Journal, Templates, Attachments, _attachments, configured periodic/template folders, and ancestors containing them; individual documents inside these folders remain removable. Folder recovery is through the OS trash, clearly stated in the confirmation and toast. Do not add a permanent delete option.
- Use Live Preview for a Markdown document with no explicit view choice, including journal creation/feed opening and ordinary note creation. Retain manual read/source/split/mindmap choices for already opened documents. Structured Canvas/Bases and explicit tool commands retain their dedicated modes.
- Explain classification on pointer hover and keyboard focus, including an unavailable review state. The classifier splits journal headings into suggestions and ranks existing folder names against heading/body text; users select targets and review a preview before applying. Copy this actual workflow, not unsupported AI/tag inference. The popup overlays content without affecting geometry.

Prefer a stable row over merely retaining stale suggestions: the latter can still change height when content becomes empty. Prefer existing file recovery plus native folder trash over introducing a second custom recursive recovery format. Scope excludes unrelated dirty documents, installed-app replacement, and automatic classification.

Success: native layout samples have unchanged editor top across dirty/saving/saved cycles; popup appears without shifting content; both Markdown types initially use live preview while explicit modes persist; right-click file/folder deletion requires confirmation, preserves unrelated paths and protected folders, and uses the correct recovery path. Both native OS release jobs and re-downloaded public assets must pass before claiming deployment.
