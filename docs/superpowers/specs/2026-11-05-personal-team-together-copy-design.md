# 개인·팀 저장소 함께 보기와 복사

2026-11-05. 브레인스토밍 설계 초안. 이 문서는 이전 대화의 공간 사이 실제 이동·원본 제거 제안을 대체한다. 제품 구현·테스트·배포 완료를 의미하지 않는다.

## 확정된 요구와 설계 가정

- 개인·팀 저장소를 전환해서만 보는 불편을 없애고 한 화면에서 동시에 연다.
- 개인에서 팀으로, 팀에서 개인으로 문서·폴더를 전달할 때 기본 동작을 복사로 통일한다. 저널의 선택 항목과 AI 대화에도 같은 규칙을 적용한다.
- 원본 저널의 본문, 날짜 구조와 관리 링크를 복사 때문에 제거하거나 변경하지 않는다.
- 복사본은 해당 시점의 독립 문서다. 이후 수정·삭제를 양쪽에 전파하는 자동 동기화는 도입하지 않는다.
- 각 공간의 물리 폴더와 Git 저장소는 분리한다. 원하는 위치의 폴더 연결과 공간 전체의 저장 위치 변경 요구도 유지한다.
- 기존 같은 공간 안의 명시적인 파일 이름 변경·이동 기능은 유지한다. 이번에 복사로 바꾸는 대상은 공간 사이 전달이다.

## 검토한 접근

| 접근 | 판단 |
| --- | --- |
| 하나의 탐색기에 공간별 트리를 두고 문서를 함께 열기 | 추천. 기존 편집 영역을 활용하며 문서의 소속을 명확히 표시할 수 있다. |
| 개인 창과 팀 창을 별도로 열기 | 동시에 볼 수 있지만 선택 항목 전달과 작업 상태 확인이 창 사이로 나뉜다. 첫 구현 범위에서 제외한다. |
| 저장소 파일들을 하나의 트리로 합치고 개인·팀 속성만 표시 | 같은 이름과 상대경로의 충돌 및 실제 Git 공유 범위가 흐려진다. 물리 저장소 통합은 하지 않는다. |

## 화면과 상호작용

두 종류의 공간이 연결되면 함께 보기를 기본으로 제공한다. 왼쪽 탐색기에 `개인 노트`와 연결된 팀 이름을 각각 루트로 표시한다. 개인·팀 필터는 표시 범위를 바꾸며 열어 둔 다른 공간의 문서나 작성 상태를 닫지 않는다.

가운데 탭과 분할 영역에는 서로 다른 공간의 문서를 함께 연다. 예를 들어 왼쪽에 개인의 오늘 저널, 오른쪽에 팀의 회의록을 둔다. 기존 Markdown 최대 3개 분할을 활용하고 분할 개수를 늘리지는 않는다. 각 탭과 영역 머리글에는 공간 이름·용도·문서 경로를 표시한다.

문서 저장, 첨부 삽입, 링크 열기, 문서 검색 결과와 편집 모드는 해당 문서의 공간을 따른다. 같은 상대경로라도 개인과 팀 문서는 별개다. 탐색기에서 다른 공간을 눌러도 커서·선택·스크롤과 저장 중 초안을 유지한다.

오른쪽 문서 정보·Git 상태·AI 대상은 초점이 있는 문서의 소속을 표시한다. AI 응답과 비동기 저장의 대상은 요청할 때의 공간·문서로 고정한다. 초점을 옮겼다고 응답의 저장 대상이 바뀌어서는 안 된다. 함께 열려 있다는 이유로 다른 공간의 본문을 AI 문맥에 자동 추가하지 않는다.

문서 검색에는 `전체 연결 공간 / 개인 / 선택한 팀` 범위를 표시한다. 결과에도 공간 이름을 붙이고 실제 소속 공간에서 연다. 이 범위 표시는 AI의 문맥 선택과 별개다.

## 드래그와 복사

문서를 편집 영역의 가장자리로 드래그하면 기존 원본을 다른 영역에 연다. 파일 복사를 발생시키지 않는다. 다른 공간의 탐색기 폴더에 드롭하면 `이 폴더에 복사`를 표시하고 복사 미리보기를 연다.

복사 미리보기에는 출발 공간, 대상 공간·폴더·문서, 복사할 내용과 필요한 첨부파일을 표시한다. 대상에 정상 저장된 뒤 대상 공간의 복사본을 연다. 원본을 지우는 후속 단계는 없다. 대상 저장소에 대한 쓰기 권한이 없거나 원본·대상이 미리보기 후 변경되면 적용을 중단한다.

전체 문서·폴더는 대상 폴더에 새 파일로 복사한다. 기존 파일을 조용히 덮어쓰거나 폴더를 병합하지 않는다. 이름이 충돌하면 다른 이름이나 다른 대상 폴더를 선택해야 한다. 저널 선택 항목은 대상의 새 Markdown 문서를 만들거나, 사용자가 지정한 기존 문서의 끝에 추가하는 미리보기를 제공한다.

저널에서는 선택한 문단·불릿과 해당 하위 불릿을 발췌한다. 선택 밖의 개인 기록을 포함하지 않는다. 화면의 선택 범위와 실제 복사 범위를 미리보기에서 일치시킨다.

AI 자동기록 제목에서 복사하면 선택한 대화의 표시된 질문·답변을 일반 Markdown 복사본으로 만든다. 묶음 전체 복사와 개별 대화 복사를 구분한다. 개인 저널의 링크와 자동기록 문서, 수집 설정, 삭제 제외 목록은 그대로다. 이후 대화는 기존 개인 수집 규칙을 따르며 팀 복사본에 덧붙이지 않는다. 내부 추론·도구 출력은 복사 범위에 추가하지 않는다.

필요한 첨부파일은 선택 내용에서 참조하는 범위만 대상 공간으로 복사하고 대상의 상대경로에 맞게 링크를 갱신한다. 출처가 개인이라는 이유로 다른 개인 문서를 자동 복사하지 않는다. 복사 범위 밖의 개인 문서에 의존하는 링크나 지원하지 않는 파일 때문에 대상을 온전히 만들 수 없으면 해당 항목을 보여 주고 적용을 중단한다. 사용자가 복사 범위에 필요한 문서를 명시적으로 추가하거나 작업을 취소할 수 있다. 팀 문서에 원본의 개인 절대경로나 관리용 메타데이터를 자동 삽입하지 않는다.

같은 출처·같은 내용·같은 대상의 반복 적용은 새 복사본이나 추가 발췌를 중복 생성하지 않는다. 원본 내용이 바뀐 뒤 다시 복사할 때는 새 복사 범위를 미리보기로 확인하며 기존 복사본을 자동 갱신하지 않는다.

## 일관된 수명 규칙

| 동작 | 원본 | 복사본 |
| --- | --- | --- |
| 다른 공간으로 복사 | 본문·링크 유지 | 선택한 내용으로 생성 |
| 원본을 편집하거나 AI 대화가 추가됨 | 정상 반영 | 그대로 유지 |
| 복사본을 편집 | 그대로 유지 | 해당 공간에서만 변경 |
| 복사본을 삭제 | 그대로 유지 | 해당 공간의 휴지통 규칙 적용 |
| 원본을 삭제 | 원본 공간의 기존 삭제 규칙 적용 | 그대로 유지 |
| 복사 실행 취소 | 그대로 유지 | 이 작업으로 만든 변경만 되돌림 |

실행 취소 시 복사본을 사용자가 추가 편집했으면 그 내용을 덮어쓰지 않는다. 충돌을 알리고 복구 사본을 보존한다. 원본 AI 자동기록의 제목 삭제는 기존의 원본 문서·저널 링크 삭제 규칙을 따르며 다른 공간의 복사본에는 전파하지 않는다.

## 저장 위치와 Git

함께 보기와 공간 간 복사는 물리 폴더를 합치거나 Git 원격·접근 권한을 변경하지 않는다. 복사 후에는 대상 공간에만 새 변경을 표시한다. 업로드는 대상 공간의 기존 Git 설정·일정에 따른다. `대상에 저장됨`, `Git 공유 대기`, `공유 완료`를 구분하고 로컬 저장을 업로드 완료로 표현하지 않는다.

개인 폴더가 팀 Git 범위 안에 들어가는 중첩 배치에 대한 현재 보호는 유지한다. 공간 용도 표시만 변경해서 이미 공유된 Git 이력이나 다른 사람의 사본을 회수했다고 표현하지 않는다.

공간 전체의 저장 위치 변경·옮긴 폴더 재연결은 별도의 설정 작업으로 제공한다. 위치가 바뀌어도 같은 공간으로 식별하여 Git 설정·저널 설정·자동기록 상태와 작업 문서를 이어받아야 한다. 새 폴더가 이전 공간과 같은 대상임을 확인하기 전에는 기존 설정을 다른 폴더에 자동 적용하지 않는다. 이 작업은 공간 사이 복사와 별도이며, 저널을 다른 공간에 넘기기 위해 원본을 제거하는 기능으로 사용하지 않는다.

## 현재 코드에서 필요한 변경 경계

- `core/document-workspace.mjs`, `src/useDocumentWorkspace.jsx`, `src/DocumentWorkspace.jsx`: 경로만 가진 문서 참조를 공간 식별자와 상대경로의 쌍으로 확장한다. 보기 모드·탭·분할·폭·AI 초안 키도 동일한 문서 참조를 따른다.
- `src/App.jsx`, `electron/main.mjs`: 현재 한 보관함을 기준으로 하는 상태와 IPC를 연결된 공간별 읽기·저장 대상으로 분리한다. 전역 선택값을 바꿔 가며 저장하는 우회 방식을 사용하지 않는다.
- `electron/vault-registry.mjs`, `core/vault.mjs`: 경로와 공간 정체성의 분리 및 기존 경로 기반 상태의 이관이 저장 위치 변경의 선행 조건이다. 등록한 공간 외의 임의 경로 접근은 허용하지 않는다.
- `core/journal-classification.mjs`: 기존의 원본을 보존하는 발췌 흐름과 revision 검사를 재사용할 수 있다. 현재는 같은 보관함만 대상으로 하므로 다른 저장소 전달을 이미 지원한다고 표현하지 않는다.
- 복사 처리는 출발·대상 revision 검증과 대상의 기존 batch/recovery 저장을 사용한다. 원본에 대한 삭제 변경을 만들지 않는다. 첨부파일 포함 작업은 부분 성공을 남기지 않도록 대상 파일 생성·복구 범위를 함께 관리한다.
- `electron/copilot-journal.mjs`, Git 서비스와 저장 큐는 공간별 상태를 유지한다. 팀 영역에 초점이 있어도 개인 자동기록이 팀 영역에 쓰이면 안 된다. 개인 공간을 닫거나 폴더가 사라지면 수집을 중단하고 해당 공간에 상태를 표시한다.

## 구현 순서와 검증 기준

첫 단계는 개인·팀 문서를 동시에 열고 각 공간에 정확하게 저장하는 동작이다. 두 공간의 `회의록.md`를 서로 다른 내용으로 편집하고 저장·재시작하여 각각의 파일만 바뀌었는지 확인한다. 보기 필터를 바꾸거나 비동기 응답 순서가 바뀌어도 탭·초안·저장 대상이 섞이지 않아야 한다.

두 번째 단계는 문서·폴더·저널 항목·AI 대화의 공간 간 복사다. 실제 임시 저장소에서 원본 파일의 해시·저널 링크·수집 상태가 복사 전후 동일한지 확인한다. 대상의 본문·첨부 경로·반복 적용·이름 충돌·쓰는 중 변경·실패 복구·되돌리기를 검증한다. 팀 복사본 편집·삭제와 원본의 후속 AI 수집이 서로 전파되지 않아야 한다.

세 번째 단계는 저장 위치 변경과 재연결이다. 경로를 바꾸거나 기존 폴더를 찾지 못하는 경우에도 원래 공간의 Git·저널·수집 설정과 문서 참조를 보존하며, 다른 폴더로 잘못 연결했을 때 설정을 덮어쓰지 않는지 검증한다.

각 단계에서 기존 단일 공간, 최대 3개 분할, Live Preview, 문서·첨부 링크, 저널 분류, 개인 자동기록과 Git 회귀를 검증한다. 네이티브 UI 검증은 임시 개인·팀 저장소만 사용한다. 이 설계 문서 작업은 실제 사용자 보관함 변경, 제품 코드 변경이나 새 공개 배포를 수행하지 않는다.
