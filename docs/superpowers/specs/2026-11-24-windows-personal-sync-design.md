# Windows 개인 보관함 연결과 재동기화

기존 개인 보관함을 Windows에서 clone한 뒤 Dynote에 등록하고 다른 PC의 첨부 파일을 받는 흐름을 검토했다. 0.23.19 기반 첫 미리보기는 기기 등록 JSON의 CRLF를 허용한다. 실제 Git으로 확인한 결과 소유권 검사 실패가 일반 오류로 표시되고, 충돌 기록 JSON에 CRLF가 있으면 같은 동기화 오류가 발생한다.

## 선택한 방법

기존 clone에서 동작하도록 Dynote의 비교와 오류 처리를 수정한다. 원격에 줄바꿈 규칙을 새로 추가하는 방식은 기존 작업 폴더에 남은 파일을 별도로 처리해야 한다. 사용자에게 파일을 다시 저장하도록 안내하는 방식은 새 기기마다 같은 작업을 요구한다.

동기화 엔진은 Git이 기록한 원본을 기준으로 기기 등록, 버전, 선택 기록의 JSON과 텍스트 문서의 충돌 사본을 확인한다. Windows 체크아웃에서 LF가 CRLF로 변환된 경우만 허용한다. 원본 커밋과 충돌 사본은 그대로 보존한다. 수정·삭제된 관리 기록과 바이너리 사본 변경은 전송을 중단하고 대상 경로를 표시한다.

Git의 소유권 거부는 최초 저장소 확인에서 사용자에게 전달한다. 사용자가 선택한 폴더 및 신뢰 설정을 확인하는 방법을 안내한다. 신뢰 범위 결정은 폴더 소유자에게 맡긴다. 공통 조상이 없는 두 저장소에는 기존 이력 보호가 적용된다.

## 완료 조건

- Windows식 체크아웃으로 기존 충돌 이력이 있는 보관함에 기기를 등록할 수 있다.
- 원본 파일, 기기 등록 내용, 첨부 파일의 바이트를 확인한다. 관리 기록의 실제 변경과 새로 추가된 관리 파일은 보존한 채 오류를 낸다.
- 소유권 거부를 재현했을 때 보관함 설정에 폴더와 원인이 표시된다. 빈 폴더와 공통 이력 검사는 기존 테스트로 회귀를 확인한다.
- 실패는 ‘동기화 중단’, 전송 시점 또는 파일 복사를 기다리는 상태는 기존 대기 문구로 표시한다. Windows 미리보기의 패키지 검증과 회사 Cloud PC 실기 확인 결과를 구분한다.
