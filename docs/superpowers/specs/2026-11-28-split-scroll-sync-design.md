# DY Note 편집기와 미리보기의 양방향 스크롤

2026-11-28 · 구현 기준 · 설계 시점 main `6bdede2`

## 사용자가 보게 될 동작

분할 모드에서 왼쪽 편집기를 내려 ‘접촉기 점검’ 문단에 도달하면 오른쪽 미리보기도 그 문단을 보여 준다. 오른쪽에서 이전 표까지 올리면 왼쪽도 해당 표의 원문 행으로 돌아간다. 휠이 놓인 쪽이 즉시 주도권을 갖는다. 스크롤만으로 편집 커서, 선택 영역, 키보드 포커스, 파일 내용이 바뀌어서는 안 된다. 적용 단위는 같은 문서 패널 안의 두 열이다. 첫 버전에서는 분할 모드 기본 동작으로 제공한다.

## 현행 동작에서 확인한 점

| 위치 | 확인한 사실 | 설계에 주는 의미 |
|---|---|---|
| `src/DocumentWorkspace.jsx`, `src/styles.css` | 두 열의 세로 위치는 주로 바깥 문서 패널이 맡고, 입력을 받은 열을 따로 기록한다. | 분할 모드에서만 두 열에 독립적으로 조절할 수 있는 세로 스크롤 영역이 필요하다. |
| `src/PaneReadingPosition.jsx`, `src/split-reading-position.mjs` | 원문 줄, 줄 안의 비율, 화면 오프셋과 마지막으로 읽은 쪽을 이용해 모드 변경·탭 복귀·재시작 위치를 복원한다. | 기존 저장 형식과 구버전 기록을 읽는 경로를 재사용한다. |
| `core/markdown-extensions.mjs`, `src/DiagramPreview.jsx` | YAML을 포함한 예제를 렌더링해 문단, 표 행, Mermaid 코드의 원문 범위를 확인했다. Mermaid는 SVG로 교체할 때 범위를 옮긴다. 같은 예제에서 블록 수식의 최종 HTML에는 원문 범위가 없었다. | 수식 출력에도 범위를 전달하고, 삽입된 다른 노트 내부는 현재 노트의 좌표에서 제외한다. |
| `src/DocumentFind.jsx`, `src/TableOfContents.jsx` | 미리보기 검색은 바깥 패널의 스크롤을 직접 바꾼다. 분할 모드 목차는 편집기 기준으로 활성 제목을 계산한다. | 검색과 목차 이동도 동기화 대상으로 연결한다. |

## 방식 비교

| 방식 | 장점 | 제약 |
|---|---|---|
| 원문 줄 범위 기준 **권장** | 표·그림 높이가 달라도 같은 문단을 찾고 기존 위치 복원 정보를 쓸 수 있다. | 두 스크롤 영역과 블록 경계를 연결해야 한다. |
| 전체 스크롤 비율 기준 | 구현이 짧고 처음과 끝을 맞추기 쉽다. | 문서 중간에 큰 그림 하나만 있어도 양쪽이 다른 내용을 가리킬 수 있다. |
| 가장 가까운 제목 기준 | 장·절 단위로 이동할 때 단순하다. | 제목이 드문 회의록이나 한 절 안의 긴 표에서 원하는 위치를 찾기 어렵다. |

## 위치 계산과 입력 처리

1. 분할 모드에서 편집기의 실제 스크롤 요소와 미리보기 세로 영역을 사용한다. 문서 헤더와 검색 UI의 실제 높이를 제외한 각 열의 본문 상단을 기준점으로 잡는다. 분할 이외 모드는 기존 스크롤 요소를 쓴다.
2. 편집기에서는 기준점에 보이는 원문 줄과 줄 안의 상대 위치를 얻는다. 미리보기에서는 기준점을 지나는 가장 구체적인 유효 블록을 고른다. 표에서는 표 전체보다 행을 우선한다. 여러 줄 문단은 기존 줄바꿈 단서와 블록 내부 비율을 이용한다.
3. 각주처럼 원문과 화면 순서가 다른 경우에도 편집기에서는 원문 줄로, 미리보기에서는 화면 좌표로 대응 블록을 찾는다. 반대쪽의 같은 원문 범위를 찾아 그쪽 스크롤만 조정한다. 도식과 수식은 블록 내부 비율로 맞춘다. 빈 줄과 숨겨진 YAML처럼 표시 대상이 없는 범위는 가장 가까운 본문 경계에 대응시킨다. 스크롤 가능한 양 끝에서는 양쪽 시작·끝을 맞추고, 한 화면에 전부 들어가는 열은 이동시키지 않는다.
4. 휠·터치·스크롤바 드래그·키보드 입력이 시작된 열을 기준으로 삼는다. 동기화가 만든 스크롤 이벤트는 반대 방향으로 재전파하지 않는다. 사용자가 다른 열에서 조작하면 이전 목표를 즉시 폐기한다. 프레임당 마지막 위치 한 번만 적용하고 부드러운 자동 스크롤은 사용하지 않는다.
5. 미리보기를 다시 그리거나 이미지·Mermaid·창 너비로 블록 높이가 변하면 마지막 사용자 위치를 기준으로 다시 맞춘다. 원문 범위 목록은 렌더링 변경 시 갱신하고, 휠 이벤트마다 전체 DOM을 순회하지 않는다. 오래된 문서의 예약 작업과 관찰자는 패널이 바뀔 때 해제한다.
6. Ctrl+F는 사용자가 선택한 검색 대상에서 먼저 결과를 보여 주고 다른 열이 따라간다. 목차 점프와 재시작 복원도 각각 한 번만 이동을 주도한다. 검색 명령이 만든 선택과 검색창 포커스, 목차 명령이 옮긴 커서와 포커스를 보존한다. 문서 A의 스크롤은 옆에 열린 문서 B에 전파하지 않는다.

## 합격 기준

- 고유 제목 아래 일반 문단을 좌우에서 각각 스크롤한다. 기존 회귀 테스트에서 두 열이 80px 넘게 어긋나는지 검사하던 단언을 교체한다. 정지 후 반대쪽 기준점이 동일한 원문 문단에 있고 일반 문단 시작 오차가 32 CSS px 이내여야 한다. 끝에서 스크롤 한계에 걸리는 경우는 양 끝 일치로 판정한다.
- 문서 중간에 정의되어 끝에 표시된 각주는 양쪽에서 같은 정의를 가리켜야 한다. 긴 표에서는 같은 행, 큰 Mermaid와 수식에서는 같은 블록을 가리켜야 한다. 그림 로딩과 너비 변경 후에도 다음 문단이 양쪽에서 일치해야 한다.
- 스크롤 방향과 조작하는 열을 빠르게 바꾼 뒤 마지막 입력 쪽이 유지된다. 입력과 레이아웃이 멈춘 후 연속 다섯 프레임 동안 양쪽 위치 변동이 각 1 CSS px 이내여야 한다.
- 긴 문서에서 커서·드래그 선택·포커스·원문을 비교한다. 휠만 조작했을 때 모두 보존되어야 한다. 검색과 목차 이동은 지정한 문단을 양쪽에 표시한다.
- 두 문서를 다른 위치에 둔 채 탭 전환, 읽기 모드 왕복, 앱 재실행을 검증한다. 기존 저장 기록으로 시작한 경우에도 마지막 읽은 문단과 열을 복원해야 한다.

문단 더블클릭으로 커서를 옮기는 기능은 별도 제안이다. 이 설계의 검증은 스크롤과 기존 탐색 동작에 한정한다.
