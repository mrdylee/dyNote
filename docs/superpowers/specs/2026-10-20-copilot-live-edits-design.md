# Copilot live document edits

User approved proceeding after actual VS Code GUI and REA investigation. Implement completed-tool-batch live edits, not simulated token animation. Alternative full token/patch streaming is deferred; existing proposal-after-answer remains only for Edit mode.

Agent emits cumulative proposals per path as each edit tool completes. Renderer overlays drafts in the center editor immediately and highlights the changed range. A request may edit the same note multiple times, but cannot broaden selection scope. Distinct file count and aggregate tool budgets stay bounded.

Drafts keep original content, revision, latest AI text, current editable draft and request identity. They live in a vault-keyed local app journal outside the vault/Git. Keep writes through existing exclusive-create/revision APIs; Undo removes a draft only if no user edits would be lost. Stop/error retain completed draft batches. Agent requests can continue with pending drafts: each request captures the current draft as its editing baseline while retaining the first original and disk revision for Keep/Undo. New unsaved notes retain their create identity across requests. Edit mode still requires pending changes to be reviewed first.

User typing stops further AI application to that document and is journalled; other documents can continue. Conflicting Undo is disabled; a read-only original/AI/current comparison and separate recovery-note save preserve all versions. Disk conflicts are checked at each batch and Keep. Switching tabs does not change targets. Closing the panel stops generation while center drafts remain. App close retains the journal; restart recovers pending drafts. Vault switching, rename/trash/reload/restore operations must not discard pending sessions. Independent ordinary notes retain autosave.

An explicit follow-up includes prior user edits, but typing after its snapshot cannot be overwritten. Permitted search/read tools see pending content; full draft snapshots never expand a selected region or grant access to unattached notes without vault permission. A document conflict retains that draft and blocks further batches for that path in the request, while other documents can continue. Existing five-document and recovery-size limits remain enforced across requests. The document title and review controls remain fixed within each scrolling pane; the original/draft comparison scrolls with the body.

Tests: cumulative tool read/edit and bounds, scoped selection/CRLF, real Electron mid-response updates, repeated batches, Keep/Undo/Stop, user typing, disk conflicts, tab switch, panel close, restart recovery, unchanged disk until Keep, and isolated package validation. Windows native IME and actual token cadence are not claimed.
