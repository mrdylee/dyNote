# Dynote 그래프 성능 개선 설계 검토

날짜: 2026-10-19. 기준: `cf44e4c`, Dynote 0.3.0. 상태: 분석 및 설계, 제품 구현 전.

## 목표와 해석

사용자의 목표는 Obsidian처럼 자연스럽게 배치되고 이동·확대·드래그가 부드러운 그래프다. 같은 점 좌표를 픽셀 단위로 재현하는 요구로 해석하지 않는다. 기능 정확성과 성능을 각각 검증하며, 현재 결과만으로 동급 성능을 달성했다고 말하지 않는다. macOS와 Windows 데스크톱을 대상으로 한다.

최신 요청은 남은 분석과 구현 진행 검토다. 앞선 구현 요청도 있으나 마지막 표현의 범위 확인 답변은 아직 없으므로, 이 문서는 구현 가능성과 순서를 구체화한 결과다.

## 확인한 사실

- 원본 Obsidian 1.12.7: PixiJS 렌더러, 별도 Worker, WASM 우선 계산, D3 fallback. 화면 밖 요소와 라벨 표시량을 줄이고 유휴 시 루프를 중단한다.
- 원본 WASM: 공간 격자 집계 계층, 중심 힘, 링크 스프링, 반발력, 충돌 완화, 속도 감쇠. REA/WABT 분석 성공. 원본 JS는 실행하지 않았다.
- 계산만 비교한 합성 시험: 1만 노드·2만 연결에서 중앙값 원본 WASM 7.01ms, D3 후보 38.24ms. Apple M4 Pro/Node 22.22.2. 화면·Worker 전송·인덱싱을 제외한 결과다.
- 현재 Dynote: 고정 나선 배치, SVG 전체 요소 출력. 노드 드래그와 물리 계산이 없다. 카메라 변경에서도 새 배열과 연결 수 계산이 반복된다.
- Dynote `buildKnowledge`: 합성 문서 5천 개·링크 1만 개의 단일 진단에서 초기 3,952ms, 문서 하나 변경 후 전체 재계산 3,873ms. 이 값은 UI 지연 실측이나 통계적 벤치마크가 아니다.
- 참고 `open-obsidian`: 노드 쌍 전체 비교와 주 스레드의 준비 계산 260회. 거리 cutoff는 힘 계산을 생략할 뿐 O(N²) 쌍 검사를 없애지 않는다.

연구 근거는 제품 외부 `../research/obsidian-1.12.7/graph-review/`에 보관한다. 원본 추출 파일과 원본 WASM을 제품 저장소·배포 파일에 포함하지 않는다.

## 접근 방법 비교

| 방법 | 장점 | 제약 | 판단 |
|---|---|---|---|
| 독립 WASM + Worker + PixiJS | 원본과 유사한 계산/표시 비용 구조를 목표로 검증 가능 | 계산 코어 개발·검증 비용, WASM/CSP 통합 필요 | 우선 후보, 코어 성능 검증부터 |
| D3 + Worker + PixiJS | 검증된 공개 API, 빠른 기능 구현 | 이번 1만 노드 조건에서 계산 약 5.5배 느림 | 비교 기준, 동급 성능이라고 전제하지 않음 |
| 참고 repo의 Canvas 그래프 도입 | 소규모 UI 참고가 쉬움 | O(N²), 주 스레드 계산, 유휴 계산 지속 | 목표 규모의 엔진으로 채택하지 않음 |

AssemblyScript는 Node 기반으로 WASM을 재현 가능하게 빌드할 후보다. 언어 채택 자체가 속도를 보장하지 않는다. 원본 코드 번역 대신 표준 공간 분할·근사 반발·스프링 알고리즘을 독립 작성하고 성능과 배치 품질을 함께 평가한다.

## 구현 단위와 순서

### 1. 데이터 및 계산 기반

`core/links.mjs`의 현재 경로 우선순위·NFC/대소문자·별칭·모호성 규칙을 보존하면서 경로/파일명/별칭 인덱스를 만든다. `buildKnowledge`는 내용이 같은 문서를 다시 파싱하지 않는다. 이름/별칭/파일 집합이 바뀌면 영향받는 링크 해석을 갱신해야 한다. 처음에는 캐시된 파싱 + 인덱스로 전체 연결을 다시 도출하는 단순한 구조를 사용하고, 충분하면 별도 의존성 캐시를 만들지 않는다.

독립 계산 코어의 입력은 연속 좌표 배열과 정수 링크 배열이다. 각 단계는 중심 힘, 링크 힘, 공간 분할 반발/충돌, 감쇠/적분을 수행한다. 겹친 점은 결정적인 작은 변위로 분리한다. 빈 그래프, 고립점, 허브, 밀집점, 중복/잘못된 링크를 테스트한다. 그래프 ID→인덱스 매핑과 유효성 검사는 JS 경계에서 한 번 수행한다.

### 2. Worker와 화면

Worker가 계산과 냉각 상태를 소유한다. 화면은 좌표만 받아 그리며 React 상태를 매 프레임 갱신하지 않는다. Worker 메시지에는 세대 번호를 넣어 필터 변경/저장소 변경 전 결과를 버린다. 전송 버퍼를 회수하여 재사용하고 이전 프레임 소비 전 추가 좌표 전송을 쌓지 않는다. 초기 버전은 transferable ArrayBuffer를 사용한다. SharedArrayBuffer와 별도 격리 헤더는 추가하지 않는다.

PixiJS의 WebGL 경로를 우선 사용하고 흰 배경을 유지한다. 화면 밖 점/라벨은 그리지 않고, 화면을 가로지르는 선은 보존한다. 라벨은 확대율·선택 상태에 따라 생성/표시한다. 정지하면 렌더 루프도 멈춘다. 화면을 떠날 때 Worker, 이벤트, RAF, GPU 자원을 해제한다.

점 클릭은 문서 열기, 일정 거리 이상 이동은 드래그로 구분한다. 포인터를 누르는 동안 위치를 고정하고 놓으면 계산을 재개한다. 배경 드래그 이동, 커서 중심 확대, 화면 맞춤, 연결 강조, 키보드 이동/확대 및 선택 문서 열기를 제공한다. Canvas 전환으로 기존 키보드 탐색을 잃지 않도록 검색 가능한 문서 선택 컨트롤을 둔다.

### 3. 그래프 기능

기존 경로/태그 필터, 전체/로컬 그래프, 깊이 1–4를 유지한다. 새 엔진에서 중심 힘·반발력·링크 힘·거리, 점 크기·선 굵기·라벨 표시량, 기본값 복원을 연결한다. 설정은 저장소별로 보관한다.

태그 점, 첨부파일 점, 미생성 링크, 고립점 표시, 검색 그룹 색상, 방향 화살표, 생성 시간 애니메이션은 원본 그래프 기능의 별도 확장 단위다. 원본 기능 목록은 [공식 Graph view 도움말](https://obsidian.md/help/plugins/graph)과 대조했다. 엔진 교체 완료를 이 기능들까지 모두 호환된 것으로 표현하지 않는다. 전체 Obsidian 검색 문법, 프런트매터 링크 인덱싱, 파일 메뉴 동작도 각각 차이 목록에 남겨 기능별로 검증한다. 모바일/Sync/Publish/Live Preview는 이번 그래프 작업 범위에 추가하지 않는다.

## 배포 및 보안 경계

현재 `notes://app`의 허용 확장자와 MIME에 번들 WASM만 추가한다. CSP에는 필요한 경우 `'wasm-unsafe-eval'`만 추가하고 일반 `'unsafe-eval'`은 허용하지 않는다. PixiJS의 해당 버전 CSP 호환 진입점을 실제 Electron에서 확인한다. CDN·외부 스크립트·네트워크 모델 의존성을 추가하지 않는다. macOS 및 Windows 패키지에 빌드한 WASM이 실제 포함되어야 한다.

## 검증과 완료 기준

1. 링크·별칭·상대경로·모호성·한글 관련 기존 결과 보존. 문서 내용 변경, 이름 변경, 별칭 변경, 저장소 변경 뒤 그래프/백링크 일치.
2. 계산 코어: 좌표 유한성, 고정점 보존, 겹침 분리, 힘 설정 효과, 빈 그래프 종료. 테스트는 좌표 스냅샷의 완전 일치를 요구하지 않는다.
3. 동일 합성 자료 1천/5천/1만 노드, 연결 밀도 2/8, 분리 집합·허브·밀집 집합에서 준비 시간과 중앙값/p95 측정. 독립 코어가 비교 원본의 1.5배 이내를 초기 내부 목표로 삼되, 품질과 다른 자료에서도 확인한 뒤 판단한다. 이것은 보장 수치가 아니다.
4. 실제 Electron: 첫 표시, 이동·확대·드래그의 프레임 시간/입력 지연, 유휴 CPU, 메모리, 단일 문서 변경 시간 측정. 비교 전 원본과 동일 화면 크기·문서 집합·표시 옵션을 맞춘다.
5. macOS/Windows 각각 실행 확인. Windows 실행 환경이 없으면 패키지 생성과 원생 실행 검증을 분리해 보고한다.

현재 51개 테스트 통과는 기존 제품의 기준 상태다. 새로운 그래프의 테스트나 성능 통과를 의미하지 않는다.
