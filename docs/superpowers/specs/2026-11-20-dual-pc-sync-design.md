# 두 PC에서 사용하는 Dynote

2026-11-20 · 설계 제안 · [상단 바와 테마 시안](2026-11-20-dual-pc-sync-preview.html)

Cloud PC에서 쓴 메모를 Local PC에서 이어 쓰고, 두 PC의 Copilot이 같은 날 만든 대화도 하나의 개인 Journal에서 연다. 두 앱은 계속 실행되며 각자 오프라인이 될 수 있다. 개인과 팀은 접근 권한이 다른 두 원격 저장소를 쓰고, 각 PC에 독립 복제본을 두는 구성을 전제로 한다.

두 번째 PC에서는 각 보관함에 ‘기존 저장소 가져오기’를 사용해 같은 브랜치를 빈 폴더에 복제한다. 동기화의 범위는 각 보관함에서 Dynote가 지원하는 파일이다. 첫 연결 시 원격·브랜치·업로드 정책을 보여준다. 팀 서버가 직접 Push를 제한하면 로컬 커밋을 보관하고 서버 거부 사유를 표시한다.

## 사용자가 PC를 바꾸는 순간

1. Local 창으로 돌아오면 현재 보관함의 원격을 즉시 확인한다. 저장할 초안이 없고 원격만 앞서 있으면 새 버전을 받아 현재 노트의 같은 위치를 보여준다. 편집 중이면 커서와 버퍼를 유지하고 상단에 ‘받을 커밋 1개’를 표시한다.
2. Cloud와 Local이 작성한 노트가 다르면 다음 동기화에서 두 커밋을 병합한다. 같은 원문에서 파생된 변경을 비교하여, 겹치지 않는 문단도 자동으로 합친다. 두 PC가 같은 문장을 다르게 고쳤으면 원문과 양쪽 변경을 함께 보여준다.
3. 팀 노트를 보고 있는 동안에도 Copilot 수집은 지정된 개인 보관함에만 기록한다. 상단 버튼은 누를 때 표시한 보관함 한 곳에만 적용한다. 보관함을 전환한 뒤 이전 요청이 끝나면 그 결과는 원래 보관함에 표시한다.

## 동기화 시점과 업로드 정책

| 계기 | 제안 동작 |
|---|---|
| 창 복귀, 보관함 전환, 네트워크 복구 | 원격 확인을 한 번 요청한다. 같은 보관함의 진행 중인 요청에 합류한다. 안전하게 받을 수 있으면 반영한다. |
| 두 창을 계속 열어 둠 | 연결된 보관함은 5분마다 원격을 확인한다. 두 PC의 타이머에는 짧은 무작위 지연을 둔다. 연결 오류면 마지막 성공 시각을 유지하고 재확인 간격을 늘린다. |
| 개인 보관함의 양방향 자동 동기화 | 두 PC에서 켜는 것을 권장한다. 실제 편집 저장이나 수집 배치 완료 후 30초간 새 쓰기가 없으면 한 번 커밋·동기화한다. 변경이 없으면 커밋하지 않는다. |
| 팀 보관함 | 신규 연결은 원격 확인과 안전한 가져오기까지 자동으로 한다. 공유할 변경이 있으면 사용자가 ‘동기화’ 또는 ‘Push’를 누른다. |
| 기존 설치 | 기존의 23시 백업 및 ‘로컬 커밋만’ 설정을 유지한다. 보관함별로 양방향 모드로 전환하면 해당 보관함에는 새 스케줄만 작동한다. ‘로컬 커밋만’에서 업로드로 바꾸려면 설정에서 직접 선택한다. |

5분과 30초는 제안 기본값이다. Copilot 수집 주기는 그대로 사용하고, Git은 수집이 실제로 기록을 남긴 뒤에만 반응한다. 개인과 팀의 대상은 각각 하나의 원격 URL과 브랜치로 고정한다. 기존 Dynote 백업 대상과 Git upstream이 다르면 설정에서 대상을 선택할 때까지 송수신을 보류한다. 개인과 팀이 동일한 원격 저장소를 가리키는 경우 연결 화면에서 분리하도록 안내한다.

## 한 보관함에서의 동기화

- 해당 보관함의 편집기와 스티키 노트 쓰기를 먼저 마친다. 미확정 Copilot 편집, 실패한 저장, 직접 스테이징한 파일, 진행 중인 외부 Git 작업이 있으면 이유를 표시하고 쓰기를 보류한다. 수집·편집 저장·Git 적용은 해당 PC의 보관함 단위로 직렬화한다. 다른 PC와의 경쟁은 원격 브랜치의 현재 커밋을 기준으로 처리한다.
- 적용 대상 변경만 로컬 커밋하고 원격 커밋을 가져온다. 동일하면 완료, 원격만 앞서면 fast-forward, 로컬만 앞서면 일반 Push, 양쪽에 커밋이 있으면 공통 조상 기준 3방향 병합을 시도한다. 로컬과 원격이 공통 이력을 갖지 않으면 자동 통합을 중단한다.
- 병합 결과는 격리된 공간에서 계산한다. 작업 폴더 반영 직전에 로컬 HEAD, 파일 내용과 열린 편집기의 변경 여부를 다시 확인한다. 달라졌으면 새 입력을 보존하고 다시 계산한다. 결과 적용 중에는 쓰기를 잠깐 직렬화하고 디스크·열린 탭·Journal 목록을 새 버전으로 함께 갱신한다.
- Push 직전 다른 PC가 먼저 올려 거부되면 최신 원격을 다시 받아 한 번만 재계산한다. 다시 경합하면 커밋을 보존하고 다음 확인으로 넘긴다. 강제 Push는 제공하지 않는다. 전송 도중 끊기면 재접속 후 해당 커밋이 원격 이력에 포함됐는지 검사하므로 재시도가 같은 내용을 또 커밋하지 않는다.
- 오프라인 중에도 기기에 저장한다. 양방향 모드에서 만든 로컬 커밋은 업로드 대상으로 보존한다. 예약 작업과 수동 버튼은 같은 보관함의 전송 작업을 공유한다. 새로 편집한 내용까지 전송됐는지는 실제 커밋 기준으로 표시한다.

## Journal과 Copilot의 병합 범위

현재 수집기는 세션 문서를 쓰고, Journal에 마커로 둘러싼 링크를 추가한다. 마커 내부에 사람이 추가한 메모와 예제 코드 속 마커도 허용된다. 수집 이력은 PC의 앱 데이터에 있고, 현재 Journal 피드는 이 로컬 목록에서 카드를 만들며 본문에서는 관리 링크를 숨긴다. 따라서 Git으로 받은 링크도 카드로 재구성해야 다른 PC에서 대화를 발견할 수 있다. 관련 소스는 [수집기](../../../electron/copilot-journal.mjs), [링크 판별](../../../core/copilot-journal-links.mjs), [Journal 피드](../../../src/JournalFeed.jsx)에 있다.

| 동시 변경 | 동작 |
|---|---|
| 같은 일지 끝에 두 개의 새 자동 링크 | 공통 원문과 비교해 양쪽이 새로 추가한 온전한 자동 링크 블록만 분리한다. 사람이 쓴 나머지 부분을 먼저 3방향 병합한 뒤, 새 블록을 안정된 ID 순서로 한 번씩 붙인다. 기존 링크 순서와 수기 문장 위치를 보존한다. |
| 두 PC가 그날의 일지를 처음 생성 | 두 문서에서 새 자동 블록을 뺀 본문이 같으면 본문 한 부와 양쪽 링크를 쓴다. 서로 다른 템플릿·메모로 시작했으면 두 원문을 비교하도록 한다. |
| 동일 링크 ID와 대상 | 같은 날짜의 동일한 자동 블록은 하나로 합친다. 같은 ID의 대상이나 편집된 내용이 다르면 검토 대상으로 둔다. |
| 삭제·편집된 기존 링크, 깨진 마커, 마커 안의 메모 | 단순 합집합으로 되살리거나 지우지 않는다. 기존 블록과 수기 텍스트는 공통 원문 기준으로 변경을 비교하고, 삭제 대 수정이나 모호한 경계는 검토 대상으로 둔다. 코드 블록 속 마커는 본문이다. |
| 서로 다른 세션 문서 | 두 파일을 모두 보존한다. 날짜별 Journal 카드에는 수신한 링크와 이 기기의 기록을 함께 표시한다. 로컬 수집 목록이 비어 있어도 수신한 세션을 열 수 있다. |
| 같은 세션 문서 | 동일 내용 또는 공통 버전에서 한쪽만 바뀐 경우 적용한다. 양쪽이 서로 다르게 변경했으면 일반 텍스트 자동 병합이 성공해도 확인한다. 현재 Markdown에는 모든 메시지 ID가 없어 대화 순서와 중복을 보장할 수 없기 때문이다. |
| 서로 다른 PC의 프로젝트 경로 | 현재 프로젝트 키는 workspace URI에서 얻는다. 같은 프로젝트라도 경로가 다르면 다른 키가 될 수 있다. v1은 제목·시간·본문 유사도로 기존 문서를 합치지 않고 두 경로를 보존한다. 이런 복제 세션은 두 카드로 보일 수 있다. |

자동 블록은 기존 파서가 인식하는 마커 두 줄과 대상 링크 한 줄만으로 이루어진 경우에만 위의 추가 규칙을 적용한다. 반복 실행 시 원격을 먼저 받은 PC에 따라 결과 순서가 달라져서는 안 된다. 세션 문서와 링크를 한 변경 묶음으로 검토하고 최종 링크가 존재하는 문서를 가리키는지 확인한다. 누락된 대상은 Journal에 ‘연결된 대화 파일 확인 필요’로 표시한다.

수신한 문서를 열거나 카드로 표시하는 일은 로컬 자동 수집의 쓰기 권한을 만들지 않는다. 각 PC는 자기 소스와 마지막 수집 원문을 기준으로 재수집한다. 받은 문서가 예상 원문과 다르거나 원격 삭제가 확인되면 해당 세션만 보류한다. 원격에서 받은 삭제 정보는 보관함별로 기억해 재수집·재시작 시 부활을 막는다. 공통 이력에 기록된 삭제는 새 PC의 최초 수집에서도 확인하고, 사용자가 명시적으로 복원할 때 해제한다. 다른 세션은 계속 수집한다. 중단된 수집 묶음은 복구 후 로컬 상태를 다시 검사한 뒤 Git에 포함한다.

## 충돌 화면과 복구

상단의 **충돌 1건 검토**를 누르면 파일명·공통 원문·이 PC·원격 변경을 보여준다. 양쪽에는 확인 가능한 작성자, 커밋, 기기 별칭을 붙인다. 팀원의 일반 Git 커밋은 실제 작성자를 표시한다. 원격 기록의 기기가 확인되지 않을 때는 ‘원격’으로 표시한다.

Markdown은 문단별 선택과 직접 편집을 지원한다. 한쪽이 지웠으면 ‘삭제 유지 / 수정본 유지’, 양쪽 PDF·이미지가 달라졌으면 ‘이 PC 파일 / 원격 파일 / 두 파일 보관’을 제공한다. 두 파일 보관 시 원본 경로에 둘 버전과 별도 파일명을 보여준다. 현재 자동 백업의 허용 목록에 DOCX는 포함되지 않으므로 대상 밖으로 표시한다. 이미 추적 중인 지원 밖 파일의 변경을 포함한 병합은 외부 Git 검토로 넘긴다.

해결 전에는 원래 두 커밋과 격리된 비교본을 보존하고 원격 업로드를 보류한다. 충돌 파일의 추가 편집은 초안으로 보관하며, 대상 파일의 자동 수집 쓰기는 보류한다. 다른 노트의 로컬 편집과 다른 보관함의 동기화는 계속할 수 있다. ‘나중에’나 앱 재시작 뒤에도 비교를 재개한다. 적용 때 로컬 파일이나 원격 HEAD가 바뀌면 최신 변경을 다시 보여주며, 이전 비교 대상을 기준으로 선택한 내용은 복구 초안으로 남긴다.

## 상단 바와 커밋 기록

고정 위치에는 **기기 → 대상 보관함 → 로컬 저장 상태 → 원격 상태 → 동기화 / Push** 순서로 표시한다. 예를 들어 ‘Cloud PC · 개인 노트 · 기기에 저장됨 · 받을 커밋 1개 · 올릴 커밋 2개’라고 읽힌다. 원격 확인 시각과 저장소·브랜치는 상태를 눌러 볼 수 있다. 마지막 확인 뒤 오프라인이 되면 ‘오프라인 · 마지막 확인 09:42’로 바뀐다.

| 상황 | 주 동작 | Push |
|---|---|---|
| 미커밋 변경 또는 원격 변경 | 동기화. 저장을 마친 뒤 해당 보관함의 지원 파일을 커밋·통합·업로드한다. 팀 공간은 버튼의 상세 설명에 업로드 범위를 표시한다. | 전송할 기존 커밋이 있고 원격을 앞설 때만 활성. 새로 저장한 미커밋 파일은 ‘커밋 전 파일’로 표시한다. |
| 양쪽 이력이 갈라짐 | 동기화. 비교와 병합을 실행한다. | ‘먼저 동기화’ 안내 |
| 충돌 또는 저장 보류 | ‘충돌 N건 검토’ 또는 ‘초안 검토’로 해당 화면을 연다. | 대상 보관함의 Push 보류 |
| 미연결, 로컬 커밋 전용, 오프라인 | 각각 ‘저장소 연결’, ‘로컬 커밋’, ‘다시 확인’을 제공한다. | 연결·정책·네트워크 상태에 따라 비활성 |

숫자의 단위를 붙인다. ‘커밋 전 파일 3개’와 ‘올릴 커밋 1개’는 함께 있을 수 있다. 원격을 확인한 이력이 없으면 수치 대신 ‘원격 확인 전’을 표시한다. 좁은 창에서는 저장 시각과 자세한 상태를 상세 패널로 옮기고 기기·보관함·주 버튼·Push는 유지한다.

설치 시 ‘Cloud PC’와 ‘Local PC’ 중 별칭을 고르거나 직접 입력한다. 설치별 난수 ID를 로컬 앱 설정에 저장하고, 기본 커밋 표기는 `회의록 수정 · by CLOUD-7F2A`로 한다. 마지막 네 자리는 식별용 표시이며 파일명이나 동기화 키로 쓰지 않는다. Dynote가 만드는 수동·자동·병합 커밋에 같은 규칙을 적용한다. Git author에는 사람의 이름과 이메일을 유지한다.

## 검증 기준

검토 과정에서 임시 bare 원격과 두 복제본으로 세 경우를 재현했다. 서로 다른 노트에서는 ff-only가 거부되고 일반 병합이 성공했다. 같은 Journal 끝에 서로 다른 자동 링크를 추가한 경우와 같은 문장을 다르게 수정한 경우에는 모두 일반 Git 병합이 충돌을 보고했다. 아래는 구현 완료를 판단할 인수 기준이다.

1. 두 PC가 같은 날짜에 다른 세션을 수집하고 한 PC는 수기 메모도 작성한다. 양쪽에서 어느 쪽이 먼저 Push해도 최종 파일 내용이 일치하고 두 세션 카드가 각각 한 번 표시·열리며 추가 동기화가 커밋을 만들지 않는다.
2. 동일 링크 중복, 독립적인 당일 Journal 최초 생성, 같은 세션의 서로 다른 본문, 마커 안의 메모, 코드 예제, 삭제 대 수정을 각각 재현한다. 안전한 경우만 자동 완료되고 나머지는 양쪽 원문으로 복구할 수 있다.
3. 오프라인 편집과 수집, 업로드 응답 유실, 연속 Push 경합, 충돌 화면에서 종료·재시작, 원격 삭제 뒤 재수집을 재현한다. 중복 전송, 누락, 삭제된 세션의 재생성이 없어야 한다.
4. Local에 어제 열어 둔 탭이나 미확정 초안이 있을 때 Cloud가 같은 노트를 수정한다. 복귀 후 오래된 버퍼가 원격 내용을 덮지 않고 초안 검토 후 이어 쓸 수 있어야 한다.
5. 팀 노트를 열어 둔 채 개인 수집이 완료되고 이어서 팀 Push를 누른다. 두 원격의 커밋 트리를 대조해 개인 기록이 개인 저장소에만 있는지 확인한다. 두 PC 재시작 후에도 테마와 별칭이 유지되고 Git에 테마 변경이 생기지 않아야 한다.
6. 두 Windows 설치에서 창 복귀, 네트워크 복구, 상단 바의 좁은 폭, 긴 한국어 보관함명, 키보드 포커스와 색 이외 상태 표시를 확인한다.
