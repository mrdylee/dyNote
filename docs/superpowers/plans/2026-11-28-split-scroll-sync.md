# DY Note 분할 화면 양방향 스크롤 구현 계획

> **For agentic workers:** 구현을 요청받으면 `superpowers:executing-plans`로 아래 단계를 순서대로 수행한다.

**목표**는 같은 문서의 편집기와 미리보기에서 양방향으로 같은 문단을 읽을 수 있게 하는 것이다.

**구조**는 분할 화면의 두 세로 스크롤 영역을 기존 원문 줄 좌표로 연결하는 방식이다. React, CodeMirror, markdown-it과 기존 Electron 검증 도구를 사용한다.

기준 커밋은 `6bdede2`이며 합격 기준은 [설계 문서](../specs/2026-11-28-split-scroll-sync-design.md)에 있다. 체크 표시는 이 브랜치에서 구현하고 검증한 항목이다.

### 1. 기존 동작을 재현하고 실패하는 검증 추가

- [x] `scripts/verify-live-preview-runtime.mjs`의 기존 긴 노트와 임시 보관함을 재사용한다. 서로 다른 높이를 강제하는 긴 표와 큰 Mermaid, 수식, 고유한 다음 문단을 넣는다. 두 번째 문서에는 감시할 문단을 열어 둔다.
- [x] 편집기 위에서 실제 휠을 굴려 첫 번째 고유 문단으로 접근하고, 미리보기 위에서 반대로 굴려 표 행까지 올라온다. 스크롤 전후의 각 열 기준점, 원문 줄 범위, 선택 영역과 포커스를 기록한다. 기존 80px 초과 단언을 교체하고, 양쪽에서 같은 문단의 위치 오차가 32px 이내인지 확인한다. 기존 공용 패널의 `scrollTop`만 비교하면 이 결함을 발견할 수 없다.
- [x] `npm run build` 후 `node scripts/verify-live-preview-runtime.mjs`를 실행해 실패가 문단 불일치에서 발생하는지 확인한다. Playwright가 외부에 설치된 환경에서는 기존 검증 스크립트의 `DYNOTE_PLAYWRIGHT_MODULE`을 사용한다.

### 2. 원문과 미리보기 좌표 연결

- [x] `tests/desktop.test.mjs`의 렌더링 검증에 YAML 다음에 나오는 블록 수식의 시작·끝 줄을 추가한다. `core/markdown-extensions.mjs`에서 수식 플러그인이 생성하는 바깥 요소에 해당 토큰의 범위를 전달하고 수식 내용은 같은 플러그인 출력으로 유지한다. `node --test tests/desktop.test.mjs`로 확인한다.
- [x] `src/PaneReadingPosition.jsx`의 문단 좌표 계산을 실시간 스크롤과 복원이 공용으로 사용하도록 분리한다. 각주를 본문 중간에 정의한 뒤 편집기와 미리보기에서 각각 이동해 원문 줄 순서와 렌더링 순서가 달라도 같은 정의를 찾는지 검증한다. 표 행과 상위 표 범위가 겹치면 해당 행을 고르고, 삽입 노트 내부 좌표는 건너뛴다. 빈 줄, 첫 본문 앞, 마지막 문단 뒤, 스크롤할 수 없는 문서에서 범위를 벗어나지 않는지 확인한다.
- [x] 반복 조회용 원문 범위와 DOM 요소의 대응은 미리보기가 바뀔 때 다시 만든다. 크기 변화 뒤에는 이전 픽셀 값을 폐기하고 현재 요소에서 좌표를 읽는다. 긴 문서 검증에서는 한 번의 휠 입력마다 전체 문서 요소가 다시 열거되는지 점검한다.

### 3. 분할 모드에 양방향 연결

- [x] `src/DocumentWorkspace.jsx`와 `src/styles.css`에서 분할 본문에 실제 남은 높이를 배정한다. CodeMirror의 `scrollDOM`과 미리보기 열이 각각 세로 스크롤되도록 하고 제목·검색창·Copilot 변경 검토 영역도 접근 가능하게 유지한다. 읽기 전용·편집 단독 화면의 레이아웃을 대조한다.
- [x] 각 문서 패널 안에서 마지막으로 직접 입력받은 열을 기록한다. 스크롤 이벤트는 다음 프레임에 모아서 반대편의 목표 위치만 갱신한다. 소수점 반올림을 허용해 프로그램이 적용한 위치를 재전파하지 않고, 새 사용자 입력이 들어오면 보류 중인 이전 목표를 버린다.
- [x] 이미지 로딩, Mermaid 교체와 크기 변화를 반영해 상대 열을 다시 맞춘다. 패널 종료·문서 교체 시 예약 프레임과 관찰자를 정리한다. 1단계 스크립트로 양방향·빠른 방향 전환·인접 패널 격리·커서 보존을 확인한다.

### 4. 검색·목차·재시작 회귀 검증

- [x] `src/DocumentFind.jsx`의 미리보기 검색 이동이 분할 모드에서는 미리보기 열을 스크롤하도록 바꾼다. `src/TableOfContents.jsx`의 활성 제목 계산과 클릭 이동 기준을 분할 본문의 실제 상단과 맞춘다. 검색 명령이 선택한 문자열과 검색창 포커스, 목차가 옮긴 커서와 편집기 포커스를 확인한다. 검색·목차가 연 이동은 사용자가 선택한 대상에서 한 번만 동기화를 시작한다.
- [x] `src/PaneReadingPosition.jsx`에서 저장·복원 시 실제 읽은 열의 스크롤 영역을 사용한다. `src/split-reading-position.mjs`의 기존 레코드를 별도 마이그레이션 없이 읽고, 오래된 복원 작업이 새 입력이나 명시적 점프보다 늦게 적용되지 않는지 확인한다.
- [x] 기존 Electron 검증에서 바깥 패널을 직접 움직이는 부분은 분할 모드일 때 실제 조작 열을 사용하도록 조정한다. 탭·재시작 후 읽던 문단, 선택한 열, 옆 문서 위치의 기존 단언은 유지한다.
- [x] `npm test`, `npm run build`, `node scripts/verify-live-preview-runtime.mjs`, `node scripts/verify-markdown-find.mjs`, `node scripts/verify-table-of-contents.mjs`를 실행한다.
- [ ] Windows에서는 휠·스크롤바 드래그·PageDown, macOS에서는 트랙패드 관성 스크롤 중 반대 열 조작을 확인하고 실행한 환경을 기록한다.

## 검증 환경

macOS arm64, Electron 44.9.1 개발 빌드와 임시 보관함을 사용했다. 변경 전에는 같은 문단을 찾는 Electron 단언과 블록 수식의 원문 줄 테스트가 실패했다. 구현 후에는 텍스트·각주·표 행의 양방향 위치, Mermaid와 수식의 원문 범위, 이미지 높이 변경, 검색·목차의 포커스, 문서별 탭 및 재시작 복원을 검증했다. 전체 테스트 720건 중 718건이 통과했고 실패는 0건이다. Windows 전용 2건은 플랫폼 조건으로 건너뛰었다. 빌드와 Electron의 스크롤·재시작, 검색, 목차, 대형 코드 블록 검증 네 가지가 통과했다. Windows의 물리 입력과 macOS 실물 트랙패드 관성은 미검증이다.
