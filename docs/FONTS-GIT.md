# 설정 · 보관함 · Git 백업과 복원

앱 메뉴의 **설정…**, 왼쪽 아래 **설정** 또는 `Cmd+,` / `Ctrl+,`를 사용합니다. **보관함·글꼴·Git 백업·백업 복원**을 선택할 수 있습니다.

이 문서의 일일 백업·보관함 관리·캘린더 복원은 v0.5.0부터 포함됩니다. v0.4.1 배포본에는 글꼴과 분 단위 Git 설정이 들어 있습니다.

## 설치 글꼴

1. **설치 글꼴 불러오기**를 누릅니다. 이 PC에 설치된 글꼴을 불러옵니다. 목록 접근이 불가능하면 설치된 글꼴 이름을 직접 입력할 수 있습니다.
2. 화면·본문·코드의 **설치 글꼴 목록**을 펼쳐 고릅니다. 목록 안에서 휠·스크롤바 또는 방향키·Page Up/Down·Home/End로 이동하고, 검색란에서 이름으로 좁힐 수 있습니다. 화면은 메뉴와 그래프 라벨, 본문은 읽기·Live Preview·Canvas 텍스트, 코드는 소스 편집과 코드 구간에 적용됩니다. 이 스크롤 목록은 v0.4.1부터 배포 ZIP에 포함됩니다.
3. 글자 크기와 본문 줄 간격을 조정합니다. 한글·영문 샘플에 반영되고 재실행 후에도 유지됩니다. 지원하지 않는 문자나 다른 PC에 없는 글꼴은 시스템 글꼴로 표시합니다.

글꼴 파일을 복사하거나 업로드하지 않으며 Markdown 내용도 바뀌지 않습니다. 설정은 해당 PC의 앱 프로필에만 저장됩니다. **글꼴 기본값 복원**으로 되돌릴 수 있습니다.

## Git 연결

Git을 설치하고 해당 저장소에 접근할 수 있는 SSH 키 또는 Git 자격 증명 로그인을 먼저 준비합니다. GitHub 웹 로그인만으로 Git 인증이 완료되는 것은 아닙니다. Dynote에서는 대화형 비밀번호 입력을 띄우지 않습니다.

저장소 주소는 나중에 입력해도 됩니다. 주소를 입력하고 연결하기 전에는 Git 자동 저장이 꺼져 있으며 로컬 파일 저장은 계속 사용할 수 있습니다.

- 새 보관함: 노트 전용 빈 원격 저장소를 만든 뒤 현재 폴더를 열고 저장소 주소·브랜치를 입력합니다. **연결하고 자동 저장 시작**을 누르면 Git 저장소를 초기화하고 첫 커밋·업로드를 실행합니다.
- 기존 원격 저장소: 주소와 기존 브랜치를 입력하고 **기존 저장소 가져오기**를 누릅니다. 비어 있는 새 폴더를 선택하면 복제 후 해당 보관함으로 전환합니다.
- 이미 복제한 폴더: Git 저장소의 루트 폴더를 열고 현재 브랜치와 같은 이름을 입력합니다. 상위 저장소에 속한 하위 폴더나 연결된 worktree는 지원하지 않습니다.

주소는 `https://github.com/사용자/노트저장소.git` 또는 `git@github.com:사용자/노트저장소.git` 형태를 지원합니다. 주소에 토큰·비밀번호를 넣지 마세요. 커밋 이름·이메일을 비우면 기존 Git 설정을 사용합니다. 사용자 Git 설정과 기존 `origin`은 변경하지 않으므로 외부 Git 도구에서 가져올 때 필요한 remote·upstream은 별도로 설정해야 할 수 있습니다.

## 저장 동작

- 로컬 자동 저장은 기존처럼 동작합니다. Git은 이 PC의 현지 시간 **밤 11시**, 보관함별 하루 한 번 실행합니다. 전날 실행을 놓쳤으면 다음 앱 시작 시 현재 파일을 백그라운드에서 백업합니다. 보충 백업도 실행한 날짜의 백업으로 계산하므로 같은 날 밤에 다시 자동 커밋하지 않습니다. 놓친 날마다 과거 상태를 만들어내지는 않습니다.
- 변경사항이 없으면 커밋하지 않습니다. 마지막 백업 확인일은 변경 여부와 무관하게 기록하여 같은 날의 불필요한 점검을 막습니다. 기존 분 단위 설정은 일일 방식으로 전환합니다. 첫 연결은 즉시 백업하며 수동 저장은 하루 한 번 제한에 포함되지 않습니다.
- **지금 Git 저장**은 현재 초안의 로컬 저장부터 마친 뒤 실행합니다. 자동 주기는 앱이 열려 있는 동안만 실행됩니다. 종료 시 마지막 원격 업로드를 기다리거나 강제로 실행하지 않습니다.
- 변경이 없으면 새 커밋을 만들지 않습니다. 원격 업로드 대신 **로컬 커밋만**도 선택할 수 있습니다.
- `.md`, `.canvas`, `.base`, PNG·JPEG·GIF·WebP·PDF의 추가·수정·이동·삭제를 반영합니다. 새 숨김 파일, 미지원 파일, 심볼릭 링크는 자동으로 추가하지 않습니다. `.gitignore`는 새 파일에 적용됩니다. **기존 Git 이력에 포함된 파일은 push할 때 함께 전송되므로 노트 전용 저장소를 사용하세요.**
- 설정은 앱 데이터의 `git-backup.json`에 보관함별로 보관합니다. 저장소 주소·브랜치·작성자·일일 일정·활성 상태·마지막 백업 확인일·업로드 대기 커밋·마지막 업로드 시간을 저장하며 인증 비밀은 저장하지 않습니다.
- 자동 커밋은 저장소 hook과 커밋 서명을 실행하지 않습니다. 서명 필수 저장소에서는 **로컬 커밋만** 또는 외부 Git 도구의 수동 작업을 사용하세요.

화면 아래 **로컬 저장 상태**와 **Git 상태**는 별개입니다. `Git 원격 저장 완료`는 해당 실행 시점의 커밋이 업로드되었음을 뜻합니다. 업로드 중 새 편집이 저장되면 다시 대기 상태가 됩니다. **자동 저장 끄기**는 주기를 중단하며, 재실행 후에도 꺼진 상태를 유지합니다.

## 오류와 다른 PC의 변경

인증·네트워크 오류가 나도 로컬 문서와 만들어진 커밋은 남습니다. 10분 뒤 또는 앱 재시작 때 재시도하며 **지금 Git 저장**으로도 다시 시도할 수 있습니다. 이미 만든 커밋은 재사용하고 이후 편집은 다음 백업으로 미룹니다. 대기 커밋을 전송한 뒤 새 편집도 즉시 올리고 싶으면 **지금 Git 저장**을 한 번 더 누릅니다. Git이 없으면 설치 후 앱을 재시작합니다.

원격에 다른 PC의 변경이 있으면 업로드를 멈추고 안내합니다. 자동 pull·rebase·강제 push·충돌 해결은 하지 않습니다. 자동 저장을 끄고 외부 Git 도구에서 이력을 통합하고 외부 Git 도구에서 업로드한 뒤 Dynote의 **문서 새로고침**을 누르고 다시 연결하세요. 직접 스테이징한 변경이나 진행 중인 merge/rebase가 있으면 해당 Git 작업을 먼저 완료해야 합니다.

이 기능은 저장소로 보내는 자동 백업입니다. 양방향 실시간 동기화는 제공하지 않습니다. 외부 Git 작업과 앱의 자동 작업을 동시에 실행하지 마세요.

## 보관함 관리

**설정 → 보관함 → 폴더 선택·추가**에서 앱 설치 폴더와 별개인 노트 폴더를 지정합니다. 등록 목록에서 다른 보관함을 열거나 사용하지 않는 항목을 제거합니다. 목록 제거는 파일을 삭제하지 않습니다. 전환 전 현재 초안을 로컬에 저장하고, 저장에 실패하면 전환을 중단합니다.

기존 `settings.json`의 `vaultRoot`를 그대로 읽으며 선택 경로와 최근 목록을 앱 데이터에 원자적으로 저장합니다. 기존 `Open Notes` 앱 데이터 위치를 유지하므로 같은 OS 사용자·앱 프로필로 실행하면 설치 파일 위치를 바꿔도 설정을 이어 씁니다. 폴더 이동·외장 디스크 분리 등으로 경로를 찾지 못하면 설정에서 알려주고 예제 보관함으로 대체하지 않습니다. 새 위치를 선택하면 됩니다. 다른 OS 사용자나 별도 `OPEN_NOTES_DATA` 프로필은 별개 설정입니다.

## 날짜별 복원

1. **설정 → 백업 복원**에서 월을 선택합니다. 표시되는 날짜는 커밋 시간의 현지 날짜입니다.
2. 백업이 있는 날짜와 해당 커밋을 고르면 추가·수정·삭제될 파일을 보여줍니다. 현재 초안은 미리보기 전에 로컬 저장합니다.
3. 변경 내용을 확인하고 **선택한 백업으로 돌아가기**를 누릅니다. 새 파일도 해당 백업에 없으면 삭제 대상이므로 목록을 확인하세요.
4. 현재 지원 파일 전체를 앱 데이터의 `recovery/<보관함 ID>/git-restore/<ID>/files/`에 복사하고, `manifest.json`에 경로·해시·시간을 기록한 뒤 복원합니다. 완료 화면에서 복구 사본 폴더를 열 수 있습니다.
5. 앱의 문서·그래프 목록을 새로 읽습니다. Git HEAD·브랜치·이력은 유지하며 복원 결과는 다음 일일/수동 백업에서 새 커밋으로 저장합니다.

현재 브랜치에서 접근 가능한 **로컬 Git 이력**을 표시하므로 업로드 전 커밋도 보입니다. 원격의 새 이력을 자동으로 가져오지는 않습니다. 지원 파일은 `.md`, `.canvas`, `.base`, PNG·JPEG·GIF·WebP·PDF이며, 숨김 설정·미지원 파일은 바꾸지 않습니다. 월별 최근 1,000개 기록, 파일당 25MB·전체 지원 파일 512MB까지 복원합니다. 문서의 앱 표시 제한은 기존 8MB입니다.

미리보기 뒤 파일이 바뀌었거나 Git에 수동 스테이징·merge/rebase가 있으면 중단합니다. 심볼릭 링크와 대소문자·유니코드 표기만 다른 충돌 경로도 중단합니다. 복원 중 쓰기 실패 시 적용한 파일을 가능한 범위에서 되돌리고 복구 사본을 남깁니다. 파일별 교체를 사용하므로 시스템 종료나 외부 프로그램의 동시 수정을 포함한 보관함 전체 트랜잭션을 보장하지 않습니다. 복구 사본은 자동 삭제하지 않습니다.
