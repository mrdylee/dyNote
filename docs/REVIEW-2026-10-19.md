# Dynote review and Canvas/Bases implementation

Reviewed baseline: `c60bc7b` (v0.2.0). Implementation branch: `feat/canvas-bases`. This was a local review; a dedicated `review-work` command was not available and no review agents were used.

## Baseline review

Read the Vault save/move/trash/recovery code, link rewriting, renderer sanitization, native protocol/IPC boundaries, SaveQueue and App integration. Re-ran all 40 baseline tests and the full dependency audit (zero known advisories). No blocking defect was reproduced in that bounded pass. Existing race limits and crash-draft limitations remain documented in README; the pass is not a full security audit.

The graph is a capability gap relative to Obsidian and the reference repository: `src/Graph.jsx` uses a deterministic spiral layout, not a force simulation, and has no individual node dragging. Canvas is a separate view. This change does not claim to improve that graph.

## Issues addressed during implementation review

- Structured files previously had no storage/recovery path. Added explicit Canvas/Bases create/save operations rather than broadening the Markdown-only public save operation.
- Added regression coverage for reference updates across note/Canvas moves, destination collisions, stale revisions, trash restoration, symlinks, unsafe Canvas paths and unknown JSON fields.
- A native UI pass found the web-card action had no usable input. Replaced the browser prompt with an explicit URL field. Unsafe external protocols still go through the existing native allowlist.
- Selection controls changed the Canvas viewport height and selected groups obscured child cards. Reserved a stable controls row and disabled automatic node elevation.
- Code review found that Bases re-evaluation cleared the previous table on every note update. Retained table elements during computation so an unrelated save does not discard another cell's in-progress DOM input; failed queries display an error and make the previous table read-only.
- Routed Canvas event handlers through current change callbacks and lock state to avoid retaining obsolete parent state.
- Added a failing regression for missing post-save file sizes, then returned current file metadata while preserving the revision of the actual bytes written.
- Bases formulas are interpreted in a local Worker. A synthetic expensive regular expression timed out with the app still responsive. Unsupported map configuration opened as read-only source without rewriting it.

## Evidence and remaining scope

51 automated tests pass. See `VERIFICATION.md` and `verification/dynote-v0.3.0-package.json` for UI, packaging and integrity evidence. Source and bundle files (174 files) match both packages; Windows runtime files match the official cached distribution. Actual Windows execution is untested.

Canvas supports basic JSON Canvas cards/connections with local viewers, not every Obsidian Canvas interaction. Bases supports Markdown rows and the documented table subset; cards/maps/kanban, summaries, plugin views, attachment rows and full Obsidian syntax/API parity remain unsupported. The third-party expression runtime is an RC package with known compatibility differences. Graph force layout, inline Live Preview, mobile, Sync/Publish and plugin compatibility were not added.
