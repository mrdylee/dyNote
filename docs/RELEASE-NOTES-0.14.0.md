# Dynote v0.14.0 — 개인·팀 노트 공간과 보안 수정

설정 → 보관함에서 **개인 노트**와 **팀 공유 노트**를 서로 다른 폴더로 연결합니다. 각 공간의 Git 설정에서 별도 저장소를 연결하고, 왼쪽 상단에서 현재 공간을 확인·전환할 수 있습니다. 기존 폴더는 사용자가 선택하기 전까지 **용도 미지정**으로 유지됩니다.

- 개인·팀 폴더가 서로 포함되거나, 반대 용도로 등록된 폴더를 연결 버튼으로 다시 분류하는 동작을 차단합니다. 의도적으로 용도를 바꾸려면 목록의 ‘공간 용도’를 사용합니다.
- 실제 Git 가져오기·업로드 주소와 Dynote 자동 백업 대상을 구분해서 표시합니다. 주소 새로고침은 로컬 Git 설정만 읽습니다.
- Copilot 하위 zod, Electron과 패키징 도구의 보안 수정 버전을 적용했습니다. 보안 검사를 배포 절차에 포함합니다.
- 기존 저널의 Tab 들여쓰기·계층형 블록, 바로 작성하기와 Markdown 크기 제한 해제를 포함합니다.

공간 용도는 구분 표시입니다. 파일을 이동하거나 Git 접근 권한·저장소 공개 범위를 바꾸지 않습니다. 개인 문서를 팀 공간에 자동 복사하지 않습니다. Git 작업은 노트 폴더 자체가 저장소 루트인 구성을 지원하며, 코드 저장소의 docs 하위 폴더·linked worktree와 자동 충돌 해결·실시간 공동 편집은 지원하지 않습니다.

AI는 선택 사항입니다. 사용할 제공자 하나만 연결하면 되며, 일반 노트 작성에 AI 로그인은 필요하지 않습니다. Claude Code 설치·로그인은 Claude를 선택할 때만 필요합니다. 기존 AI 선택과 문서·템플릿을 유지합니다. Word·Excel 보기 기능은 이번 버전에 포함되지 않습니다.

## 설치

Apple Silicon Mac: `Dynote-0.14.0-macos-arm64.dmg`를 열고 Dynote를 Applications 폴더로 옮깁니다. **이 베타 앱은 ad-hoc 무결성 서명이며 Developer ID 배포 서명·Apple 공증이 없어 macOS에서 실행을 차단할 수 있습니다.** 다운로드 출처와 체크섬을 확인하고 시스템 설정의 앱별 열기 허용 여부를 직접 결정하세요.

Windows x64: `Dynote-0.14.0-windows-x64.zip` 전체를 풀고 `Dynote-win32-x64/Dynote.exe`를 실행합니다. EXE 옆의 resources·DLL도 함께 있어야 합니다.

교체 전에 기존 앱을 정상 종료하세요. 기존 노트 폴더·앱 데이터는 유지됩니다. 플랫폼별 `SHA256SUMS-*.txt`로 다운로드 무결성을 확인할 수 있습니다. 앱 내 업데이트에서 시험판을 받으려면 베타 포함 설정을 확인하세요.

## 검증 범위

Mac arm64와 Windows x64의 네이티브 CI에서 단위 테스트, 전체 의존성 보안 검사, 패키징, 실제 앱의 개인·팀 연결·저장·전환·복원·Git·AI 검토 저장·저널 흐름을 실행합니다. 두 플랫폼의 검증과 배포 파일 체크섬이 모두 통과해야 공개 베타로 게시됩니다.

AI 응답 검사는 결정적 테스트 이벤트를 사용합니다. 실제 사용자 계정 로그인·유료 모델 추론, Windows ARM·Intel Mac·Linux 실행과 장기간 운영 안정성은 이번 검증 범위에 포함되지 않습니다.
