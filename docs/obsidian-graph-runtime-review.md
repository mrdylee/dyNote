# Obsidian 그래프 실제 실행 검토

날짜: 2026-10-19. 대상: 설치된 Obsidian 1.12.7, macOS / Apple M4 Pro.

## 실행 조건

사용자가 설치된 앱의 실행·관찰을 허용한 뒤, 네이티브 UI로 별도의 합성 보관함을 열었다. 기존 개인 보관함의 문서를 테스트 입력으로 사용하지 않았다. 테스트 폴더에는 커뮤니티 플러그인을 넣지 않았다.

| 보관함 | Markdown 문서 | 방향 있는 문서 링크 | 구조 |
|---|---:|---:|---|
| Dynote-Graph-1000 | 1,000 | 2,000 | 각 문서가 `(i+1)%N`, `(i+31)%N` 문서를 참조 |
| Dynote-Graph-10000 | 10,000 | 20,000 | 같은 패턴, 폴더당 100개 문서 |

각 문서에 폴더별 태그 하나를 넣었다. 태그 점 표시와 첨부 표시의 기본 설정은 꺼져 있었다. 실행 후 11,000개 Markdown 파일을 생성 내용과 비교해 모두 동일함을 확인했다. Obsidian이 테스트 보관함에 만든 설정과 캐시는 유지했다.

테스트 자료: 제품 외부 `../research/obsidian-1.12.7/graph-review/runtime-vaults/`. 입력 검증: 같은 연구 폴더의 `runtime-fixture-verification.json`. UI 상태 및 화면 근거는 이 작업 대화의 Computer Use 결과에 있다. 이 관찰은 이전 REA 정적 Evidence나 계산 모듈 벤치마크와 구분한다.

## 직접 확인한 동작

| 항목 | 관찰 결과 | Dynote에 반영할 의미 |
|---|---|---|
| 1천 문서 그래프 | 점과 연결선이 나타나고 시간에 따라 위치가 재배치됨 | 고정 나선 배치를 물리 배치로 교체 |
| 경로 검색 | `path:group-000` 입력 후 해당 폴더 이름의 문서들로 화면이 바뀜 | 기존 단순 경로 입력과 검색 문법 지원을 구별 |
| 축소/확대 | 축소 시 라벨이 생략되고 확대하면 희미하게 나타난 뒤 읽을 수 있게 됨 | 임계치 하나로 전부 표시하기보다 확대율에 따른 투명도 적용 |
| 노드 클릭 | `Note-00044` 점을 클릭하자 해당 Markdown 문서로 이동 | 클릭과 드래그를 구별하고 기존 문서 열기 유지 |
| 로컬 그래프 | 명령 팔레트에서 선택 문서와 나란히 열림. 중심 Note-00044와 이웃 13/43/45/75가 표시됨 | 전체 화면만 전환하는 방식 외에 문서와 함께 보는 용도 고려 |
| 로컬 깊이 | 슬라이더를 1→2로 바꾸자 노드 범위가 늘어남 | 그래프 깊이 적용 검증 필요 |
| 로컬 방향 옵션 | 들어오는 링크·나가는 링크·이웃 링크를 각각 켜고 끄는 UI 확인 | 단순 양방향 BFS만으로 기능 동등성을 주장할 수 없음 |
| 표시/힘 설정 | 화살표, 텍스트 표시 시작점, 점 크기, 선 굵기, 중심력·반발력·링크 힘·거리 UI 확인 | 표시와 물리 조절을 따로 제공 |
| 1만 문서 그래프 | 인덱싱 완료 알림과 그래프 표시 확인. 휠 축소와 배경 드래그로 화면이 변경됨 | 적어도 이 규모의 보관함을 실제 원본에서 열고 조작할 수 있음을 확인 |
| 전체 조망 | 1만 문서를 모으면 이름이 사라지고 점/선이 조밀한 덩어리로 보임 | 전체 표시만으로 가독성은 해결되지 않음. 필터·로컬 탐색을 함께 개선 |

1천 문서 로컬 그래프의 이웃은 입력과 일치한다: 들어오는 링크는 13→44, 43→44이고 나가는 링크는 44→45, 44→75다. 깊이 2의 전체 노드 개수를 런타임 내부 데이터로 세지는 않았다.

그래프 내 노드 드래그는 시도했으나 버튼을 누르는 동안의 좌표와 놓은 직후의 복원 동작을 분리 계측하지 않았다. 따라서 고정 좌표 유지·재가열·손을 놓은 뒤 이동 규칙은 이번 실행으로 완전히 검증한 항목이 아니다. 배경 드래그는 전체 그래프 위치 변경으로 확인했다.

## 측정으로 주장하지 않는 항목

- 이 관찰에서는 FPS, 프레임 p95, 입력 지연, 최초 표시 시간, CPU/메모리를 계측하지 않았다. 자동화 호출의 응답 시간은 앱 표시 시간으로 사용하지 않는다.
- 화면이 조작에 반응했다는 사실과 60 FPS 유지 여부는 다르다.
- 이번 실행의 WASM/JavaScript fallback 선택은 런타임 계측으로 확인하지 않았다. 앞선 패키지 분석은 WASM 우선 시도와 fallback 경로의 존재를 확인한 결과다.
- 앞선 7ms 대 38ms 수치는 Node에서 계산 모듈만 비교한 값이다. 실제 앱의 전체 성능 수치로 바꾸어 인용하지 않는다.
- 실제 그래프 내부의 노드·링크 수를 읽은 것은 아니다. 1천/1만 및 2천/2만은 생성·검증한 입력의 개수다.
- Windows 실행 및 Dynote의 새 엔진과 나란히 비교하는 시험은 수행하지 않았다.

## 구현 판단

성능 엔진 개선 방향은 유지한다. 다만 사용자에게 느껴지는 완성도는 물리 배치뿐 아니라 라벨의 확대율 반응, 연결 강조, 필터, 문서와 함께 보는 로컬 그래프에서도 나온다. GPU 렌더러 하나만 붙여 동등해졌다고 판단하면 안 된다.

우선 단위는 링크 인덱스·재파싱 비용 개선, 독립 계산 코어 검증, Worker와 렌더러 연결이다. 로컬 방향 옵션을 데이터 모델 설계에 반영하고, 로컬 그래프의 분할 보기와 추가 원본 기능은 엔진 완료와 구분해 구현한다. 세부 동작 및 프레임 성능은 새 Dynote 그래프가 실행되는 시점에 같은 입력으로 나란히 측정한다.

현재 Dynote 제품 코드는 변경하지 않았다. 실제 실행 검토 결과와 구현 계획만 보완했다.
